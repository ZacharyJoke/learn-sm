# 练习 01 命令行体验 SM3 摘要

## 目标

- 确认本机 OpenSSL 已支持 SM3（OpenSSL 1.1.1+）。
- 用命令行计算空串与 `abc` 的 SM3 摘要，并与国家标准向量逐字符比对。
- 亲手制造「改一个字符，摘要全变」的雪崩效应。
- 对比 SM3、MD5、SHA-256 的输出长度，建立杂凑算法的直观认识。

## 前置条件

- macOS / Linux 命令行环境（Windows 可用 WSL 或 Git Bash）。
- 已安装 OpenSSL 1.1.1 或更高版本；如使用 GmSSL 3 也可，命令写法以实际 help 为准。
- 无需任何密码学基础。

## 环境/路径

新建并进入练习目录：

```bash
mkdir -p ~/gm-practice/01-sm3 && cd ~/gm-practice/01-sm3
openssl version
```

记录 `openssl version` 输出，方便排查版本差异。

## 详细步骤

### 步骤 1：确认 SM3 可用

先查看 dgst 支持的算法列表中是否包含 SM3：

```bash
openssl dgst -list 2>/dev/null | tr ' ' '\n' | grep -i sm3
```

> 提示：不同版本输出格式可能不同，如该过滤命令无输出，可直接执行下一步；若 `-sm3` 参数报错，说明版本过旧或未编译国密支持，请升级 OpenSSL 或改用 GmSSL 3。

### 步骤 2：计算空串摘要并对照标准向量

```bash
printf "" | openssl dgst -sm3
```

标准向量（空串）：

```text
1ab21d8355cfa17f8e61194831e81a8f22bec8c728fefb747ed035eb5082aa2b
```

### 步骤 3：计算 `abc` 摘要并对照标准向量

注意必须用 `echo -n` 去掉末尾换行，否则输入其实是 `abc\n`，结果对不上：

```bash
echo -n "abc" | openssl dgst -sm3
```

标准向量（`abc`）：

```text
66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0
```

### 步骤 4：观察雪崩效应——改一个字符

连续计算三条只有细微差异的输入：

```bash
echo -n "hello" | openssl dgst -sm3
echo -n "hellO" | openssl dgst -sm3
echo -n "hello " | openssl dgst -sm3
```

对比三条摘要：即使只改一个字母大小写或加一个空格，输出也截然不同，看不出任何关联——这就是雪崩效应。

### 步骤 5：对比 MD5 / SHA-256 的输出长度

对同一输入分别计算三种摘要：

```bash
echo -n "abc" | openssl dgst -md5
echo -n "abc" | openssl dgst -sha256
echo -n "abc" | openssl dgst -sm3
```

## 执行命令（汇总，可一次复制执行）

```bash
cd ~/gm-practice/01-sm3
openssl version
printf "" | openssl dgst -sm3
echo -n "abc" | openssl dgst -sm3
echo -n "hello"  | openssl dgst -sm3
echo -n "hellO"  | openssl dgst -sm3
echo -n "hello " | openssl dgst -sm3
echo -n "abc" | openssl dgst -md5
echo -n "abc" | openssl dgst -sha256
echo -n "abc" | openssl dgst -sm3
```

## 预期输出

| 输入    | 算法      | 预期摘要                                                               | 长度（十六进制字符）   |
| ----- | ------- | ------------------------------------------------------------------ | ------------ |
| 空串    | SM3     | `1ab21d8355cfa17f8e61194831e81a8f22bec8c728fefb747ed035eb5082aa2b` | 64（=256 bit） |
| `abc` | SM3     | `66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0` | 64           |
| `abc` | MD5     | `900150983cd24fb0d6963f7d28e17f72`                                 | 32（=128 bit） |
| `abc` | SHA-256 | `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad` | 64（=256 bit） |

实际命令输出会带 `(stdin)= ` 之类的前缀，比对时只看等号后面的十六进制字符串即可，不同版本前缀格式略有差异。

## 扩展思考

1. 同样是 256 bit，SM3 和 SHA-256 对 `abc` 的结果为什么完全不同？（压缩函数不同）
2. 如果用 `echo "abc"`（不带 `-n`）结果对不上标准向量，为什么？
3. 摘要长度固定为 256 bit，为什么能给任意大的文件做「指纹」？会不会有两个文件指纹相同？
4. 为什么下载站公布文件摘要可以防「意外损坏」，但若摘要和文件放在同一处、又不做签名，并不能防恶意篡改？

## 常见失败排查

- **`unknown option '-sm3'` / `invalid digest`**：OpenSSL 版本低于 1.1.1 或未启用国密。执行 `openssl version` 确认，升级后重试，或安装 GmSSL 3。
- **`abc` 结果与标准向量不符**：多半是漏了 `-n`，输入里混入了换行；用 `printf '%s' abc` 可替代。
- **grep 过滤无输出但命令能跑**：不同版本 `-list` 输出格式不同，以实际计算结果为准。
- **macOS 自带 LibreSSL**：部分 macOS 自带的是 LibreSSL，可能不支持 `-sm3`，可用 Homebrew 安装 OpenSSL（如 `brew install openssl@3`）并用其完整路径调用。
