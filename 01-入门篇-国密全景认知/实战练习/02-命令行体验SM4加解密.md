# 练习 02 命令行体验 SM4 加解密

## 目标

- 用 `openssl enc -sm4-cbc` 完成一次「加密 → 解密」往返，还原原文。
- 观察相同明文使用不同 IV 时密文完全不同。
- 观察用错误密钥解密时的现象（乱码或报错），理解「密钥错误则无法还原」。
- 牢记密钥与 IV 必须使用密码学安全随机数生成（`openssl rand -hex 16`）。

## 前置条件

- 已完成练习 01，确认 OpenSSL（1.1.1+）支持 SM3。
- OpenSSL 支持 `-sm4-cbc`（1.1.1+ 内建；GmSSL 3 同样支持，参数以实际 help 为准）。

## 环境/路径

```bash
mkdir -p ~/gm-practice/02-sm4 && cd ~/gm-practice/02-sm4
openssl version
```

## 详细步骤

### 步骤 1：随机生成密钥与 IV

SM4 密钥长度为 128 bit = 16 字节 = 32 个十六进制字符；CBC 模式的 IV 同样是 16 字节：

```bash
KEY=$(openssl rand -hex 16)
IV=$(openssl rand -hex 16)
echo "KEY=$KEY"
echo "IV=$IV"
```

> 纪律：密钥与 IV 都必须随机生成。IV 不需要保密，但**同一密钥下绝不能固定/重用 IV**；密钥必须保密。

### 步骤 2：准备明文文件

```bash
printf '国密 SM4 加解密往返测试 hello\n' > plain.txt
cat plain.txt
```

### 步骤 3：加密

```bash
openssl enc -sm4-cbc -K "$KEY" -iv "$IV" -in plain.txt -out cipher.bin
cat cipher.bin
```

屏幕显示的是不可读的二进制乱码。也可以查看十六进制内容：

```bash
xxd cipher.bin | head
```

### 步骤 4：正确密钥解密，完成往返

```bash
openssl enc -d -sm4-cbc -K "$KEY" -iv "$IV" -in cipher.bin -out recovered.txt
cat recovered.txt
diff plain.txt recovered.txt && echo "往返一致 OK"
```

### 步骤 5：相同明文、不同 IV → 密文不同

保持密钥不变，换一个随机 IV 再加密：

```bash
IV2=$(openssl rand -hex 16)
openssl enc -sm4-cbc -K "$KEY" -iv "$IV2" -in plain.txt -out cipher2.bin
xxd cipher.bin  | head -2
xxd cipher2.bin | head -2
cmp cipher.bin cipher2.bin || echo "不同 IV 密文不同（符合预期）"
```

### 步骤 6：错误密钥解密现象

用一把错误密钥尝试解密：

```bash
WRONG_KEY=$(openssl rand -hex 16)
openssl enc -d -sm4-cbc -K "$WRONG_KEY" -iv "$IV" -in cipher.bin -out wrong.out
cat wrong.out
```

## 执行命令（汇总）

```bash
cd ~/gm-practice/02-sm4
KEY=$(openssl rand -hex 16)
IV=$(openssl rand -hex 16)
printf '国密 SM4 加解密往返测试 hello\n' > plain.txt
openssl enc -sm4-cbc -K "$KEY" -iv "$IV" -in plain.txt -out cipher.bin
openssl enc -d -sm4-cbc -K "$KEY" -iv "$IV" -in cipher.bin -out recovered.txt
diff plain.txt recovered.txt && echo "往返一致 OK"
IV2=$(openssl rand -hex 16)
openssl enc -sm4-cbc -K "$KEY" -iv "$IV2" -in plain.txt -out cipher2.bin
cmp cipher.bin cipher2.bin || echo "不同 IV 密文不同（符合预期）"
WRONG_KEY=$(openssl rand -hex 16)
openssl enc -d -sm4-cbc -K "$WRONG_KEY" -iv "$IV" -in cipher.bin -out wrong.out; echo "退出码=$?"
```

## 预期输出

- `diff plain.txt recovered.txt` 无差异，并打印 `往返一致 OK`。
- 两次加密的密文 `cipher.bin` 与 `cipher2.bin` 字节不同，打印 `不同 IV 密文不同（符合预期）`。
- 错误密钥解密：`wrong.out` 为乱码；多数情况下因为 PKCS#7 填充校验失败，命令会报 `bad decrypt` 并给出非 0 退出码。是否报错取决于随机结果，**乱码或报错都属于预期现象**。

> 说明：不同 OpenSSL 版本对填充校验、错误提示文案可能略有差异，以本机实际输出为准。

## 扩展思考

1. IV 不保密，为什么还要保护它、为什么不能在同一密钥下重用？
2. CBC 模式为什么需要填充？明文恰好是 16 字节整数倍时还要不要填充？
3. 密钥在命令行里以 `-K` 明文出现，会留在 shell 历史里——真实工程中这有什么风险？该如何管理密钥？
4. 如果想要「不需要填充、可并行」的模式，CTR 模式相比 CBC 有什么特点？想要同时加密+校验完整性，可考虑什么模式（如 GCM）？

## 常见失败排查

- **`invalid hex key value` / `invalid hex iv value`**：长度不对或含非十六进制字符，必须正好 32 个十六进制字符，用 `openssl rand -hex 16` 生成。
- **`unknown cipher '-sm4-cbc'`**：OpenSSL 版本过低，用 `openssl enc -list | grep -i sm4` 确认，必要时升级或改用 GmSSL 3。
- **解密报 `bad decrypt`**：密钥/IV 用错，或密文被改动；先核对加解密使用的 KEY、IV 是否完全一致。
- **中文乱码**：终端编码问题，比较文件用 `diff`/`cmp` 而非肉眼判断。
- **变量在新终端失效**：`KEY`/`IV` 只在当前 shell 有效，重新打开终端需重新生成，或把值显式写在命令中（仅练习用途）。
