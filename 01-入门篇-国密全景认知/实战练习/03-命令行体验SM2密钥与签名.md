# 练习 03 命令行体验 SM2 密钥与签名

## 目标

- 用 `openssl ecparam` 生成 SM2 私钥，并导出对应公钥。
- 用 SM2 私钥生成 CSR，查看其中的曲线 OID，确认用的是 sm2p256v1。
- 尝试用命令行完成一次 SM2 签名 / 验签。
- 重点观察：**同一明文连续两次签名，签名值不同（非确定性签名）**。

## 前置条件

- 已完成练习 01、02。
- OpenSSL 1.1.1+（建议了解本机版本；3.x 与 1.1.1 的 SM2 签名命令差异较大）。

> 版本纪律：SM2 签名在不同 OpenSSL 版本中的参数和子命令差异明显，本练习给出常见写法；**实际执行前请先看 `openssl dgst -help`、`openssl pkeyutl -help` 的本机输出，参数以实际 help 为准**，不必死记。

## 环境/路径

```bash
mkdir -p ~/gm-practice/03-sm2 && cd ~/gm-practice/03-sm2
openssl version
```

## 详细步骤

### 步骤 1：查看支持的曲线中是否有 SM2

```bash
openssl ecparam -list_curves | grep -i sm2
```

预期能看到 `SM2`（不同版本描述文案可能为 `SM2 curve` 等）。

### 步骤 2：生成 SM2 私钥

```bash
openssl ecparam -genkey -name SM2 -out sm2.key
cat sm2.key
```

查看私钥内部信息（可看到曲线与参数）：

```bash
openssl ec -in sm2.key -text -noout
```

### 步骤 3：导出公钥

```bash
openssl ec -in sm2.key -pubout -out sm2.pub
cat sm2.pub
```

### 步骤 4：生成 CSR 并查看曲线 OID

```bash
openssl req -new -key sm2.key -sm3 -subj "/CN=demo" -out sm2.csr
openssl req -in sm2.csr -text -noout | grep -i -A2 "ASYM"
openssl asn1parse -in sm2.csr | grep -i "1.2.156.10197"
```

SM2 曲线 OID 以 `1.2.156.10197` 开头（sm2p256v1 的 OID 为 `1.2.156.10197.1.301`）。grep 匹配不到时，可直接执行 `openssl req -in sm2.csr -text -noout` 全文查看 `Public Key Algorithm` 与曲线字段。

### 步骤 5：尝试签名 / 验签（参数随版本不同）

准备消息文件（用文件而非管道，便于复现）：

```bash
echo -n "sm2 signing test" > msg.txt
```

**常见方式 A（OpenSSL 3.x，dgst 方式）：**

```bash
openssl dgst -sm3 -sign sm2.key -out sig1.bin msg.txt
openssl dgst -sm3 -verify sm2.pub -signature sig1.bin msg.txt
```

**常见方式 B（pkeyutl 方式）：**

```bash
openssl pkeyutl -sign -inkey sm2.key -rawin -in msg.txt -out sig1.bin
openssl pkeyutl -verify -pubin -inkey sm2.pub -rawin -in msg.txt -sigfile sig1.bin
```

> 如果上述命令报错（如缺少 `-rawin`、提示需要 SM2 专用处理、`scheme` 相关错误），说明你的版本参数不同，请以 `openssl dgst -help` / `openssl pkeyutl -help` 为准调整，或参考 GmSSL 3 的命令。本练习**不强求某一条特定命令成功**，核心目标是完成密钥生成与非确定性观察。

### 步骤 6：观察非确定性签名——同一明文两次签名值不同

用步骤 5 中能跑通的那种方式连续签两次：

```bash
openssl dgst -sm3 -sign sm2.key -out sig1.bin msg.txt
openssl dgst -sm3 -sign sm2.key -out sig2.bin msg.txt
xxd sig1.bin
xxd sig2.bin
cmp sig1.bin sig2.bin || echo "两次签名值不同（符合预期）"
```

两份签名都能用同一个公钥验证通过，但字节不同：因为 SM2 签名过程引入了随机数。

## 执行命令（汇总，按本机可用方式选择）

```bash
cd ~/gm-practice/03-sm2
openssl ecparam -list_curves | grep -i sm2
openssl ecparam -genkey -name SM2 -out sm2.key
openssl ec -in sm2.key -pubout -out sm2.pub
openssl req -new -key sm2.key -sm3 -subj "/CN=demo" -out sm2.csr
openssl req -in sm2.csr -text -noout | grep -i -A2 "algorithm"
echo -n "sm2 signing test" > msg.txt
openssl dgst -sm3 -sign sm2.key -out sig1.bin msg.txt
openssl dgst -sm3 -sign sm2.key -out sig2.bin msg.txt
openssl dgst -sm3 -verify sm2.pub -signature sig1.bin msg.txt
cmp sig1.bin sig2.bin || echo "两次签名值不同（符合预期）"
```

## 扩展思考

1. 两次签名值不同，为什么验证者都能确认是同一把私钥所签？（验证只依赖公钥、消息与签名中的数学关系，不依赖固定签名值）
2. SM2 签名内部为什么用 SM3？如果消息很大，是直接签消息还是先摘要？
3. 私钥文件 `sm2.key` 当前以明文 PEM 保存，真实环境该如何保护（口令加密、HSM/KMS、权限控制）？
4. SM2 除了签名，还能做公钥加密和密钥交换，它们分别对应什么需求？

## 常见失败排查

- **`unknown curve name 'SM2'`**：OpenSSL 版本过低或未启用国密，先升级到 1.1.1+（建议 3.x）或用 GmSSL 3。
- **签名命令报参数错误**：3.x 与 1.1.1 参数不同，先查 `openssl dgst -help`、`openssl pkeyutl -help`，尝试 `-rawin` 或 dgst 方式。
- **grep OID 无输出**：不同命令输出位置不同，用 `openssl req -in sm2.csr -text -noout` 全文查看，或用 `openssl asn1parse -in sm2.csr` 手动浏览。
- **验签失败**：消息文件生成时是否混入换行（两次操作要一致）、公钥是否由该私钥导出、签名与验签算法是否都为 SM3withSM2。
- **macOS 自带 LibreSSL**：不支持 SM2 曲线时，安装并使用 Homebrew 的 OpenSSL 3。
