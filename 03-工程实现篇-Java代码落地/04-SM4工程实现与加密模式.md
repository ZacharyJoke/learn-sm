# 04 · SM4 工程实现与加密模式

> 一句话价值：用对 GCM/CBC/CTR 与填充，把随机 IV/nonce、密钥版本和 AEAD 校验做成统一载荷格式，杜绝 nonce 复用这一致命错误。

---

## 🧭 核心概念

- **SM4 是 128 位分组对称密码**：分组 16 字节，**密钥固定 128 bit（16 字节）**。加密解密同一把密钥，速度比 SM2 快得多，业务数据加密都用它。
- **分组密码本身只能加密 16 字节**，要处理任意长度数据必须选**工作模式**：
  - **GCM**：CTR 流式加密 + GHASH 完整性校验，属于 **AEAD（带关联数据的认证加密）**，输出密文 + 认证标签 tag，**新系统默认首选**；
  - **CBC**：密文分组链接，历史最常见，需要填充，**只有机密性没有完整性**；
  - **CTR**：把分组密码转成密钥流，明文等长、无需填充，同样**没有完整性**；
  - **ECB**：每块独立加密，相同明文块产生相同密文块，**禁止用于业务数据**（仅用于标准向量验证）。
- **IV/nonce 不需要保密，但必须随密文一起传给解密方**；它的安全要求不是随机到「保密」，而是**在同一密钥下绝不重复**（GCM）/ 不可预测（CBC）。

### 贯穿本篇的场景

某政务 SaaS 要把用户的**手机号、身份证号等 PII 字段加密后入库**：用 SM4-GCM 加密，AAD 绑定 `租户ID + 字段名`（密文被搬到别的租户/别的字段即解密失败），密钥由第 6 篇的 KMS 体系管理。对接的两个老系统分别只支持 CBC、CTR，因此同时给出三种模式的实现与统一载荷。

## ⚙️ 工作原理

### GCM 认证加密

```mermaid
flowchart LR
    K[SM4 密钥] --> H[H = SM4K(0^128)<br>GHASH 子密钥]
    K --> C[CTR 计数器加密<br>生成密钥流]
    N[96bit nonce] --> C
    P[明文] --> CT[密文 C]
    C --> CT
    A[AAD] --> G[GHASH: 对 AAD‖C 求多项式 MAC]
    CT --> G
    H --> G
    N --> T[tag = GHASH ⊕ 加密计数器0]
    G --> T
```

- JCE 中 GCM 密文输出为 `ciphertext ‖ tag`（tag 默认追加在末尾）；解密时自动校验 tag，不通过抛 `AEADBadTagException`。
- **AAD（Additional Authenticated Data）**：只参与完整性校验、不被加密。适合绑定 `keyId`、租户、字段名、版本号等上下文——密文离开这个上下文就无法通过校验。

### 统一载荷格式

```text
version(1B) ‖ keyVersion(2B) ‖ iv/nonce(12B 或 16B) ‖ ciphertext(‖tag 仅 GCM)
```

| 字段 | 长度 | 含义 |
|---|---|---|
| `version` | 1 字节 | 载荷格式版本（当前 `0x01`，GCM/12B nonce/tag128）；升级格式时据此分流 |
| `keyVersion` | 2 字节 | 加密所用密钥版本号（大端）；解密时查对应版本的密钥（见第 6 篇） |
| `iv/nonce` | GCM 12 字节；CBC/CTR 16 字节 | 每次加密新生成，随密文存储/传输 |
| `ciphertext` | 明文等长（CTR/GCM）或按填充对齐（CBC） | GCM 时末尾含 16 字节 tag |

## 🛠 工程方法与 API

### 模式参数对比表

| 模式（transformation） | IV 长度 | 填充 | 完整性 | nonce/IV 安全要求 | 适用 |
|---|---|---|---|---|---|
| `SM4/GCM/NoPadding` | 12 字节（推荐） | 无 | ✅ 128bit tag | **同密钥下 nonce 绝不重复** | 新系统默认 |
| `SM4/CBC/PKCS5Padding` | 16 字节 | PKCS#7（JCE 名 PKCS5） | ❌ 需另配 HMAC | 每次不可预测 | 兼容老系统 |
| `SM4/CTR/NoPadding` | 16 字节 | 无 | ❌ 需另配 HMAC | **同密钥下 IV 绝不重复** | 流式/等长场景 |
| `SM4/ECB/NoPadding` | 无 | 无 | ❌ | —— | **业务禁用**，仅测试向量 |

> JCE 名称里的 `PKCS5Padding` 在分组为 16 字节时等价于 **PKCS#7**，不是缺陷。

### 1）密钥生成

```java
import org.bouncycastle.jce.provider.BouncyCastleProvider;

import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import java.security.Security;
import java.util.HexFormat;

public final class Sm4KeyGenerator {

    private static final String BC = "BC";

    static {
        if (Security.getProvider(BC) == null) {
            Security.addProvider(new BouncyCastleProvider());
        }
    }

    private Sm4KeyGenerator() {
    }

    /** 生成 128bit SM4 密钥。生产中密钥应来自 KMS，本方法用于演示/DEK 本地生成。 */
    public static SecretKey generate() {
        try {
            KeyGenerator kg = KeyGenerator.getInstance("SM4", BC);
            kg.init(128, java.security.SecureRandom.getInstanceStrong());
            return kg.generateKey();
        } catch (Exception e) {
            throw new IllegalStateException("SM4 密钥生成失败", e);
        }
    }

    public static void main(String[] args) {
        System.out.println(HexFormat.of().formatHex(generate().getEncoded()));
    }
}
```

### 2）载荷打包/解析

```java
import java.nio.ByteBuffer;

public record Sm4Payload(byte version, int keyVersion, byte[] iv, byte[] ciphertext) {

    public static final byte V1 = 0x01;
    public static final int GCM_NONCE_LEN = 12;
    public static final int BLOCK_IV_LEN = 16;

    public byte[] pack() {
        ByteBuffer bb = ByteBuffer.allocate(1 + 2 + iv.length + ciphertext.length);
        bb.put(version).putShort((short) keyVersion).put(iv).put(ciphertext);
        return bb.array();
    }

    /** version=0x01 且使用 GCM（nonce 12B）；其它版本按对应布局解析。 */
    public static Sm4Payload parseGcm(byte[] packed) {
        ByteBuffer bb = ByteBuffer.wrap(packed);
        byte version = bb.get();
        if (version != V1) {
            throw new IllegalArgumentException("不支持的载荷版本: " + version);
        }
        int keyVersion = Short.toUnsignedInt(bb.getShort());
        byte[] nonce = new byte[GCM_NONCE_LEN];
        bb.get(nonce);
        byte[] ciphertext = new byte[bb.remaining()];
        bb.get(ciphertext);
        return new Sm4Payload(version, keyVersion, nonce, ciphertext);
    }
}
```

### 3）GCM：PII 字段加密（含 AAD）

```java
import javax.crypto.Cipher;
import javax.crypto.spec.GCMParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.security.SecureRandom;

public final class Sm4Gcm {

    private static final String BC = "BC";
    private static final int TAG_BITS = 128;
    private static final int NONCE_LEN = 12;

    private Sm4Gcm() {
    }

    /** 生成完整载荷：version‖keyVersion‖nonce‖ciphertext‖tag。 */
    public static byte[] encryptField(byte[] key, int keyVersion, String fieldName,
                                      String tenantId, String plaintext) {
        try {
            byte[] nonce = new byte[NONCE_LEN];
            SecureRandom.getInstanceStrong().nextBytes(nonce);

            Cipher cipher = Cipher.getInstance("SM4/GCM/NoPadding", BC);
            cipher.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(key, "SM4"),
                    new GCMParameterSpec(TAG_BITS, nonce));
            cipher.updateAAD(buildAad(tenantId, fieldName)); // 绑定上下文
            byte[] ciphertextAndTag = cipher.doFinal(plaintext.getBytes(StandardCharsets.UTF_8));

            return new Sm4Payload(Sm4Payload.V1, keyVersion, nonce, ciphertextAndTag).pack();
        } catch (Exception e) {
            throw new IllegalStateException("SM4-GCM 加密失败", e);
        }
    }

    public static String decryptField(byte[] key, String fieldName,
                                      String tenantId, byte[] packed) {
        try {
            Sm4Payload p = Sm4Payload.parseGcm(packed);
            Cipher cipher = Cipher.getInstance("SM4/GCM/NoPadding", BC);
            cipher.init(Cipher.DECRYPT_MODE, new SecretKeySpec(key, "SM4"),
                    new GCMParameterSpec(TAG_BITS, p.iv()));
            cipher.updateAAD(buildAad(tenantId, fieldName));
            byte[] plain = cipher.doFinal(p.ciphertext()); // tag 校验失败抛 AEADBadTagException
            return new String(plain, StandardCharsets.UTF_8);
        } catch (Exception e) {
            throw new IllegalStateException("SM4-GCM 解密失败", e);
        }
    }

    private static byte[] buildAad(String tenantId, String fieldName) {
        return (tenantId + ":" + fieldName).getBytes(StandardCharsets.UTF_8);
    }
}
```

使用：

```java
public class PiiDemo {

    public static void main(String[] args) {
        // 生产：密钥从 KMS 按 keyVersion 取，绝不硬编码
        byte[] key = java.util.HexFormat.of().parseHex(System.getenv("GM_SM4_KEY"));

        byte[] packed = Sm4Gcm.encryptField(key, 3, "idCardNo", "TENANT-1001", "110101199001011234");
        String value = Sm4Gcm.decryptField(key, "idCardNo", "TENANT-1001", packed);

        System.out.println(value); // 110101199001011234
    }
}
```

### 4）CBC（对接老系统）

```java
import javax.crypto.Cipher;
import javax.crypto.spec.IvParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.security.SecureRandom;

public final class Sm4Cbc {

    private static final String BC = "BC";
    private static final int IV_LEN = 16;

    private Sm4Cbc() {
    }

    public static byte[] encrypt(byte[] key, byte[] plaintext) {
        try {
            byte[] iv = new byte[IV_LEN];
            new SecureRandom().nextBytes(iv); // 每次新随机 IV，随密文返回

            Cipher cipher = Cipher.getInstance("SM4/CBC/PKCS5Padding", BC);
            cipher.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(key, "SM4"), new IvParameterSpec(iv));
            byte[] ciphertext = cipher.doFinal(plaintext);

            byte[] out = new byte[IV_LEN + ciphertext.length];
            System.arraycopy(iv, 0, out, 0, IV_LEN);
            System.arraycopy(ciphertext, 0, out, IV_LEN, ciphertext.length);
            return out;
        } catch (Exception e) {
            throw new IllegalStateException("SM4-CBC 加密失败", e);
        }
    }

    public static byte[] decrypt(byte[] key, byte[] ivAndCiphertext) {
        try {
            byte[] iv = new byte[IV_LEN];
            byte[] ciphertext = new byte[ivAndCiphertext.length - IV_LEN];
            System.arraycopy(ivAndCiphertext, 0, iv, 0, IV_LEN);
            System.arraycopy(ivAndCiphertext, IV_LEN, ciphertext, 0, ciphertext.length);

            Cipher cipher = Cipher.getInstance("SM4/CBC/PKCS5Padding", BC);
            cipher.init(Cipher.DECRYPT_MODE, new SecretKeySpec(key, "SM4"), new IvParameterSpec(iv));
            return cipher.doFinal(ciphertext);
        } catch (Exception e) {
            throw new IllegalStateException("SM4-CBC 解密失败", e);
        }
    }
}
```

> CBC 没有完整性：攻击者改密文后解密可能产生「填充错误」信号，形成 padding-oracle 攻击。要么上层叠加 HMAC（**先加密后 MAC，HMAC 覆盖 IV+密文**），要么升级 GCM。

### 5）CTR（流式/等长，对接老系统）

```java
import javax.crypto.Cipher;
import javax.crypto.spec.IvParameterSpec;
import javax.crypto.spec.SecretKeySpec;
import java.security.SecureRandom;

public final class Sm4Ctr {

    private static final String BC = "BC";
    private static final int IV_LEN = 16;

    private Sm4Ctr() {
    }

    public static byte[] encrypt(byte[] key, byte[] plaintext) {
        try {
            byte[] iv = new byte[IV_LEN];
            SecureRandom.getInstanceStrong().nextBytes(iv);

            Cipher cipher = Cipher.getInstance("SM4/CTR/NoPadding", BC);
            cipher.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(key, "SM4"), new IvParameterSpec(iv));
            byte[] ciphertext = cipher.doFinal(plaintext);

            byte[] out = new byte[IV_LEN + ciphertext.length];
            System.arraycopy(iv, 0, out, 0, IV_LEN);
            System.arraycopy(ciphertext, 0, out, IV_LEN, ciphertext.length);
            return out;
        } catch (Exception e) {
            throw new IllegalStateException("SM4-CTR 加密失败", e);
        }
    }

    public static byte[] decrypt(byte[] key, byte[] ivAndCiphertext) {
        try {
            byte[] iv = new byte[IV_LEN];
            byte[] ciphertext = new byte[ivAndCiphertext.length - IV_LEN];
            System.arraycopy(ivAndCiphertext, 0, iv, 0, IV_LEN);
            System.arraycopy(ivAndCiphertext, IV_LEN, ciphertext, 0, ciphertext.length);

            Cipher cipher = Cipher.getInstance("SM4/CTR/NoPadding", BC);
            cipher.init(Cipher.DECRYPT_MODE, new SecretKeySpec(key, "SM4"), new IvParameterSpec(iv));
            return cipher.doFinal(ciphertext);
        } catch (Exception e) {
            throw new IllegalStateException("SM4-CTR 解密失败", e);
        }
    }
}
```

## 💥 GCM nonce 复用为什么是灾难（必须理解）

GCM 在同一密钥下复用同一 nonce 加密两条消息时：

1. **机密性崩**：GCM 的加密部分本质是 CTR，同一 nonce 生成同一密钥流。`C1 XOR C2 = P1 XOR P2`，攻击者拿到两条密文就能还原明文之间的关系，已知其中一条明文即得另一条。
2. **完整性崩**：GHASH 使用由 nonce/密钥确定的认证子密钥 H。两组 `(AAD, 密文, tag)` 联立可解出 H，之后攻击者能为**任意伪造密文算出合法 tag**，AEAD 形同虚设。
3. 实践中这通常不是「被攻击」而是**工程事故**：计数器被重置、多实例用相同固定前缀、容器扩容后状态丢失、测试把 nonce 写死后带进生产。

CTR 模式同密钥重复 IV 的后果是上面第 1 条（密钥流复用）。

**防护措施**：

- nonce 由 `SecureRandom` 每次新生成 12 字节，绝不手工指定/来自时间戳；
- 随机 nonce 方案下，**单密钥加密量远低于碰撞界**（NIST 建议单密钥随机 nonce 不超过约 2^32 次）；高并发场景改用「计数器型 nonce（含分片/实例位）」或在达到量级前轮换密钥；
- 多实例部署优先计数器分配（协调服务/实例 ID 占高位），避免各自随机的管理盲区；
- 加密代码评审把「nonce 来源」列为必查项。

## 🏗 生产取舍

| 取舍点 | 建议 |
|---|---|
| GCM vs CBC | 新系统一律 GCM（自带完整性）；CBC 仅用于无法升级的对接方，且必须加密后 MAC |
| 随机 nonce vs 计数器 nonce | 普通业务量随机 12B 最简单；超高吞吐/多活用计数器并设计实例位 |
| tag 长度 | 固定 128bit；不要为省空间截短到 96bit 以下 |
| AAD 放什么 | keyId、租户、字段名、协议版本；不要把本身需要保密的数据放 AAD（它不加密） |
| 字段加密与查询 | 加密后无法等值模糊查询；需要检索时另存 `HMAC-SM3(DEK_fpe?, 值)` 盲索引或用格式保留方案，不要退回 ECB |

## ❓ 常见问题

**Q1：IV 每次随机，解密方怎么知道 IV？**
IV 不保密，按载荷格式拼在密文前面一起存/传，解析时先切出来。

**Q2：同一明文每次密文不同是对的吗？**
对，正是随机 IV 的意义。测试断言「解密回来相等」，不要断言密文相等。

**Q3：GCM 解密抛 `AEADBadTagException` 意味着什么？**
密文/AAD 被篡改、密钥不对、nonce 不匹配，或密文属于另一个上下文。按「校验失败」处理，不要尝试返回部分明文。

**Q4：CBC 的 IV 可以全零固定吗？**
不行。相同首块明文会暴露关联，且 CBC 的安全依赖 IV 不可预测；每次随机。

## ✅ 最佳实践 / ❌ 反模式

- ✅ 新代码统一 `SM4/GCM/NoPadding`，12B 随机 nonce + 128bit tag
- ✅ AAD 绑定 keyId/租户/字段等上下文，载荷带 version + keyVersion
- ✅ IV/nonce 与密文一起返回，格式全项目统一
- ✅ 必须用 CBC 时，加密后对 `IV‖密文` 做 HMAC
- ❌ ECB 加密任何业务数据
- ❌ 固定 nonce、时间戳 nonce、多实例共享同一计数器起点
- ❌ GCM tag 校验失败仍使用解出的明文
- ❌ 把 IV 当密钥保密、或把 AAD 当加密通道放敏感数据

---

## 🚫 什么时候不要这样做

- **不要为了「兼容」用 ECB**：哪怕只加密一个字段，相同值密文相同本身就是信息泄露。
- **不要在没有完整性保护的链路上传输 CBC/CTR 密文**：可被无声篡改。
- **不要在单密钥高频加密时继续用随机 nonce 而不设轮换阈值**：碰撞概率随加密次数平方增长。
- **不要自创模式组合**（如 CBC 后自己异或一层固定串）：需要什么性质，直接选标准模式与标准 MAC。

---

## 🕳 常见坑点

1. **nonce 长度用 16 字节**：GCM 推荐 12 字节；16B 时部分库对 nonce 做 GHASH 再派生计数器，跨库互通容易出分歧。
2. **解密没留够 tag 位置**：输入必须包含末尾 16B tag，截断后必然 `AEADBadTagException`。
3. **AAD 两边拼不一致**：多一个冒号、顺序换了都会失败；像定义签名串一样书面固定 AAD 模板。
4. **CBC 密文长度不是 16 的倍数**：传输/存储被字符串转码破坏，byte[] 要走二进制通道（Base64 仅在边界）。
5. **把 `getInstanceStrong()` 与业务线程池混用导致启动阻塞**：见第 5 篇熵源排障。
