# 练习 02 · SM4 文本加解密（GCM 模式）

用国密对称密码 SM4 的 GCM 模式完成一次安全的文本加密/解密往返，并亲手验证「随机 Nonce」与「篡改必被发现」两条安全性质。

---

## 🎯 练习目标

- 用 `KeyGenerator` 随机生成 128 位 SM4 密钥
- 用 `SM4/GCM/NoPadding` 完成加密与解密
- 密文封装格式为 `Base64(nonce || ciphertext || tag)`，解密时正确拆段
- 通过实验确认：相同明文每次密文不同（随机 nonce）
- 通过负向实验确认：篡改 1 个字节即抛出 `AEADBadTagException`
- 理解为什么禁止 ECB、为什么 nonce/iv 必须随密文传递

---

## 📋 前置条件

**知识准备**

- 对称加密：加密和解密用同一把密钥
- GCM 是「加密 + 完整性校验」的认证加密模式（AEAD），输出 = 密文 + 认证标签 tag
- nonce（Number used once）：GCM 建议 12 字节随机；同一把密钥下 **nonce 绝不能重复**
- Base64：把任意字节序列变成可打印文本的编码方式（不是加密！）

**环境准备**

- JDK 17+、Maven 3.8+
- 已完成练习 01（已会引入 BC、注册 Provider）
- 统一练习目录：`~/gm-practices/`

### 步骤 3：编写完整 Java 代码

文件路径：`~/gm-practices/gm-sm4-demo/src/main/java/com/example/gm/Sm4GcmDemo.java`

```java
package com.example.gm;

import org.bouncycastle.jce.provider.BouncyCastleProvider;

import javax.crypto.AEADBadTagException;
import javax.crypto.Cipher;
import javax.crypto.KeyGenerator;
import javax.crypto.SecretKey;
import javax.crypto.spec.GCMParameterSpec;
import java.nio.charset.StandardCharsets;
import java.security.SecureRandom;
import java.security.Security;
import java.util.Arrays;
import java.util.Base64;

public class Sm4GcmDemo {

    static final int NONCE_LEN = 12;
    static final int TAG_BITS = 128;
    static final Base64.Encoder B64_ENC = Base64.getEncoder();
    static final Base64.Decoder B64_DEC = Base64.getDecoder();

    public static void main(String[] args) throws Exception {
        Security.addProvider(new BouncyCastleProvider());

        SecretKey key = generateKey();
        String plain = "你好，国密 SM4！这是一段需要保密的文本。";

        String cipher1 = encrypt(plain, key);
        String cipher2 = encrypt(plain, key);

        System.out.println("明文     : " + plain);
        System.out.println("密文 1   : " + cipher1);
        System.out.println("密文 2   : " + cipher2);
        System.out.println("两次密文不同（随机 nonce）: " + !cipher1.equals(cipher2));

        String decrypted = decrypt(cipher1, key);
        System.out.println("解密还原 : " + decrypted);
        System.out.println("往返一致 : " + decrypted.equals(plain));

        tamperDemo(cipher1, key);
    }

    /** 加密：输出 Base64(nonce(12) || ciphertext || tag(16))。 */
    static String encrypt(String plain, SecretKey key) throws Exception {
        byte[] nonce = new byte[NONCE_LEN];
        new SecureRandom().nextBytes(nonce);

        Cipher cipher = Cipher.getInstance("SM4/GCM/NoPadding", "BC");
        cipher.init(Cipher.ENCRYPT_MODE, key, new GCMParameterSpec(TAG_BITS, nonce));
        byte[] sealed = cipher.doFinal(plain.getBytes(StandardCharsets.UTF_8));

        byte[] packed = new byte[nonce.length + sealed.length];
        System.arraycopy(nonce, 0, packed, 0, nonce.length);
        System.arraycopy(sealed, 0, packed, nonce.length, sealed.length);
        return B64_ENC.encodeToString(packed);
    }

    /** 解密：拆出 nonce 与 sealed（ciphertext||tag），GCM 会自动校验 tag。 */
    static String decrypt(String packedBase64, SecretKey key) throws Exception {
        byte[] packed = B64_DEC.decode(packedBase64);
        byte[] nonce = Arrays.copyOfRange(packed, 0, NONCE_LEN);
        byte[] sealed = Arrays.copyOfRange(packed, NONCE_LEN, packed.length);

        Cipher cipher = Cipher.getInstance("SM4/GCM/NoPadding", "BC");
        cipher.init(Cipher.DECRYPT_MODE, key, new GCMParameterSpec(TAG_BITS, nonce));
        return new String(cipher.doFinal(sealed), StandardCharsets.UTF_8);
    }

    /** 负向实验：篡改 1 个字节，GCM 必须能发现。 */
    static void tamperDemo(String cipherBase64, SecretKey key) {
        try {
            byte[] packed = B64_DEC.decode(cipherBase64);
            packed[packed.length - 1] ^= 1;
            decrypt(B64_ENC.encodeToString(packed), key);
            System.out.println("篡改未被发现？！这不应该发生");
        } catch (AEADBadTagException e) {
            System.out.println("篡改检测: AEADBadTagException -> " + e.getMessage());
        } catch (Exception e) {
            System.out.println("篡改检测（其他异常）: " + e.getClass().getSimpleName());
        }
    }

    /** 随机生成 128 位 SM4 密钥。生产环境应改为从 KMS / 环境变量注入。 */
    static SecretKey generateKey() throws Exception {
        KeyGenerator keyGenerator = KeyGenerator.getInstance("SM4", "BC");
        keyGenerator.init(128);
        return keyGenerator.generateKey();
    }
}
```

### 步骤 4（可选但推荐了解）：生产环境密钥外部注入

随机密钥每次重启就变，只适合演示。真实工程密钥来自环境变量/KMS，代码中**零硬编码**：

```java
static SecretKey loadKeyFromEnv() {
    String keyHex = System.getenv("SM4_KEY_HEX"); // 32 个 Hex 字符 = 16 字节
    if (keyHex == null || keyHex.isBlank()) {
        throw new IllegalStateException("环境变量 SM4_KEY_HEX 未设置");
    }
    byte[] keyBytes = HexFormat.of().parseHex(keyHex);
    return new SecretKeySpec(keyBytes, "SM4");
}
```

注入示例（密钥由部署平台/KMS 下发，不要写进代码仓库）：

```bash
export SM4_KEY_HEX=$(openssl rand -hex 16)
```

> 生产环境请使用 KMS、HSM 或集中密钥管理系统，不要用 shell 生成后长期明文存放。

## 🧩 扩展思考

1. 如果 nonce 不随机、固定写死，且同一把密钥加密了多条消息，会带来什么风险？（提示：GCM nonce 复用会严重削弱安全性）
2. 解密方只拿到 `Base64(nonce||ciphertext||tag)`，为什么不需要额外约定 nonce 值？
3. 尝试篡改 nonce 而不是密文，会发生什么？
4. GCM 还支持 AAD（附加认证数据），什么场景下需要 AAD？（提示：要保护但不需要加密的头信息）
5. 如果业务历史包袱必须用 CBC，至少要做到哪三点？（随机 IV、IV 随密文、只用它解决保密性而完整性另想办法）

> 备选模式：`SM4/CBC/PKCS5Padding`，IV 为 16 字节随机数，同样前缀随密文。CBC 只提供保密性，不提供完整性，新项目默认选 GCM。

## 🧯 常见失败与排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `NoSuchAlgorithmException: SM4/GCM/NoPadding` | BC 未注册或算法名写错 | 注册 Provider；算法名严格写作 `SM4/GCM/NoPadding` |
| `InvalidAlgorithmParameterException: Unsupported tag size` | tag 长度给错 | `GCMParameterSpec` 第一个参数是 **bit 数**，用 128（不是 16） |
| `AEADBadTagException` 在正常解密时就抛出 | nonce 拆段错位，或密文被当字符串处理过 | 严格按字节拆段；密文链路中不要经过 `new String()` |
| 解密中文乱码 | 解密后未用 UTF-8 | `new String(bytes, StandardCharsets.UTF_8)` |
| 两次密文相同 | nonce 写死了 | nonce 必须每次 `SecureRandom` 生成 |
| Base64 解码报错 | 复制密文时混入空格/换行 | 完整复制，或改用 URL 安全 Base64 场景再评估 |
