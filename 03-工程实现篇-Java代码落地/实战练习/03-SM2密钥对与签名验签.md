# 练习 03 · SM2 密钥对与签名验签

生成人生第一对 SM2 非对称密钥，用私钥对业务消息做数字签名、用公钥验证签名，并亲手验证「换用户 ID」「篡改消息」都会让验签失败。

---

## 🎯 练习目标

- 在 `sm2p256v1`（SM2 推荐椭圆曲线）上生成 SM2 密钥对
- 按工程常用格式导出公钥：`04 || X || Y`（未压缩椭圆曲线点，65 字节，Hex 以 `04` 开头）
- 用 `SM3withSM2` 算法签名，并通过 `SM2ParameterSpec` 指定签名者用户 ID
- 用公钥完成验签
- 验证三个事实：签名值每次不同；篡改消息验签失败；换用户 ID 验签失败

---

## 📋 前置条件

**知识准备**

- 非对称密码：密钥成对出现，私钥签名/解密（必须保密），公钥验签/加密（可以公开）
- SM2 签名是「SM3 摘要 + SM2 签名运算」，JCE 算法名 `SM3withSM2`
- **用户 ID（ZA）**：SM2 签名会把签名者身份标识纳入杂凑计算；签名与验签必须使用同一个 ID，标准默认 ID 为 `1234567812345678`
- 签名中含随机数 k，因此同一条消息每次签名值都不同，但都能验签通过
- JCE 返回的签名值是 ASN.1 DER 编码（`30` 开头的 SEQUENCE），不是固定长度裸 r‖s

**环境准备**

- JDK 17+、Maven 3.8+，已完成练习 01、02

### 步骤 3：编写完整 Java 代码

文件路径：`~/gm-practices/gm-sm2-sign-demo/src/main/java/com/example/gm/Sm2SignDemo.java`

```java
package com.example.gm;

import org.bouncycastle.jcajce.provider.asymmetric.ec.BCECPrivateKey;
import org.bouncycastle.jcajce.provider.asymmetric.ec.BCECPublicKey;
import org.bouncycastle.jcajce.spec.SM2ParameterSpec;
import org.bouncycastle.jce.provider.BouncyCastleProvider;

import java.nio.charset.StandardCharsets;
import java.security.KeyPair;
import java.security.KeyPairGenerator;
import java.security.SecureRandom;
import java.security.Security;
import java.security.Signature;
import java.security.spec.ECGenParameterSpec;
import java.util.HexFormat;

public class Sm2SignDemo {

    static final HexFormat HEX = HexFormat.of();
    static final byte[] DEFAULT_USER_ID = "1234567812345678".getBytes(StandardCharsets.UTF_8);
    static final byte[] OTHER_USER_ID = "alice@example.com".getBytes(StandardCharsets.UTF_8);

    public static void main(String[] args) throws Exception {
        Security.addProvider(new BouncyCastleProvider());

        KeyPair keyPair = generateKeyPair();
        BCECPublicKey publicKey = (BCECPublicKey) keyPair.getPublic();
        BCECPrivateKey privateKey = (BCECPrivateKey) keyPair.getPrivate();

        byte[] q = publicKey.getQ().getEncoded(false);
        System.out.println("公钥 Q（04||X||Y，" + q.length + " 字节）:");
        System.out.println(HEX.formatHex(q));
        System.out.println("私钥 D: 32 字节（保密，不打印）");

        String message = "订单号 A20260922001，金额 100.00 元";

        String signature1 = sign(keyPair, message, DEFAULT_USER_ID);
        String signature2 = sign(keyPair, message, DEFAULT_USER_ID);

        System.out.println("消息   : " + message);
        System.out.println("签名 1 : " + signature1);
        System.out.println("签名 2 : " + signature2);
        System.out.println("两次签名不同（随机数 k）: " + !signature1.equals(signature2));

        System.out.println("验签（同消息同 ID）: "
                + verify(keyPair, message, signature1, DEFAULT_USER_ID));
        System.out.println("验签（篡改消息）  : "
                + verify(keyPair, "订单号 A20260922001，金额 0.01 元", signature1, DEFAULT_USER_ID));
        System.out.println("验签（换用户 ID） : "
                + verify(keyPair, message, signature1, OTHER_USER_ID));
    }

    static KeyPair generateKeyPair() throws Exception {
        KeyPairGenerator keyPairGenerator = KeyPairGenerator.getInstance("EC", "BC");
        keyPairGenerator.initialize(new ECGenParameterSpec("sm2p256v1"), new SecureRandom());
        return keyPairGenerator.generateKeyPair();
    }

    static String sign(KeyPair keyPair, String message, byte[] userId) throws Exception {
        Signature signature = Signature.getInstance("SM3withSM2", "BC");
        signature.setParameter(new SM2ParameterSpec(userId));
        signature.initSign(keyPair.getPrivate(), new SecureRandom());
        signature.update(message.getBytes(StandardCharsets.UTF_8));
        return HEX.formatHex(signature.sign());
    }

    static boolean verify(KeyPair keyPair, String message, String signatureHex, byte[] userId) throws Exception {
        Signature signature = Signature.getInstance("SM3withSM2", "BC");
        signature.setParameter(new SM2ParameterSpec(userId));
        signature.initVerify(keyPair.getPublic());
        signature.update(message.getBytes(StandardCharsets.UTF_8));
        return signature.verify(HEX.parseHex(signatureHex));
    }
}
```

关键 API 说明：

- `getQ().getEncoded(false)`：`false` 表示未压缩格式，得到 `04 || X坐标(32) || Y坐标(32)` 共 65 字节；这也是 GM/T 0009 中 SM2 公钥的常见交换格式。
- `signature.setParameter(new SM2ParameterSpec(userId))`：必须在 `initSign/initVerify` 前后按 BC 支持的时机设置；签名与验签双方的用户 ID 必须一致。
- `initSign(privateKey, new SecureRandom())`：显式传入随机源，签名中的随机数 k 来自它。

## 🧯 常见失败与排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `InvalidAlgorithmParameterException: unknown curve name` | 曲线名写错 | 严格写作 `sm2p256v1` |
| 验签恒为 `false` | 签名/验签用户 ID 不一致，或消息字节不一致 | 统一 ID；消息统一 UTF-8，确认没有多余换行/空格 |
| `InvalidKeyException` | 把非 SM2 曲线的密钥用于 SM2 签名 | 密钥对必须在 `sm2p256v1` 上生成 |
| 公钥不是 `04` 开头 | 打印的是 `getEncoded()` 的 X.509 格式（`30` 开头） | 用 `getQ().getEncoded(false)` 取裸点 |
| `NoSuchAlgorithmException: SM3withSM2` | BC 未注册 | 注册 `BouncyCastleProvider` |
| 跨系统解析签名失败 | DER 与裸 r‖s 混淆 | 双方约定编码格式，DER 是 JCE 默认输出 |

> API 版本提示：`setParameter` 的调用时机在不同 JCA 实现中可能有差异，本文写法基于 bcprov-jdk18on 1.84 实测；升级版本时以该版 Javadoc 为准。
