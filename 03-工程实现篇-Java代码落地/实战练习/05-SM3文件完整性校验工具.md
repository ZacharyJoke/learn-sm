# 练习 05 · SM3 文件完整性校验工具

开发一个命令行小工具：给一个目录递归生成「文件清单（manifest）」，之后随时用清单校验目录里的文件是否被改动、删除。这是发布包校验、配置防篡改最常见的工程形态。

---

## 🎯 练习目标

- 用 `Files.walk` 递归收集目录下的全部普通文件
- 对每个文件做流式 SM3 摘要（8KB 缓冲，可处理大文件）
- 生成清单文件：每行 `SM3 Hex + 两个空格 + 相对路径`（兼容 `sha256sum` 风格）
- 实现 `verify` 子命令：逐文件重新计算，输出 `OK / FAILED` 列表
- 篡改任意文件（或删除文件）后，校验必须能检出并以非零退出码结束

---

## 📋 前置条件

**知识准备**

- 清单文件要与被保护数据分开存放/传递，否则攻击者连清单一起改就失去意义（后续可对清单再签名）
- 相对路径保证清单可以随目录整体搬迁后仍然可用
- 流式处理：`MessageDigest.update()` 分块喂数据，内存占用恒定
- 校验工具的退出码可被脚本/CI 消费：全部 OK 返回 0，存在失败返回 1

**环境准备**

- JDK 17+、Maven 3.8+，已完成练习 01

### 步骤 3：编写完整 Java 代码

文件路径：`~/gm-practices/gm-file-hash/src/main/java/com/example/gm/ManifestTool.java`

```java
package com.example.gm;

import org.bouncycastle.jce.provider.BouncyCastleProvider;

import java.io.BufferedWriter;
import java.io.InputStream;
import java.io.OutputStreamWriter;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.security.MessageDigest;
import java.security.Security;
import java.util.ArrayList;
import java.util.Comparator;
import java.util.HexFormat;
import java.util.List;
import java.util.stream.Stream;

public class ManifestTool {

    private static final int BUFFER_SIZE = 8192;

    public static void main(String[] args) throws Exception {
        Security.addProvider(new BouncyCastleProvider());
        if (args.length != 3 || (!args[0].equals("generate") && !args[0].equals("verify"))) {
            System.out.println("Usage: ManifestTool generate <dir> <manifest>");
            System.out.println("       ManifestTool verify   <dir> <manifest>");
            System.exit(1);
        }
        Path dir = Path.of(args[1]).toAbsolutePath().normalize();
        Path manifest = Path.of(args[2]).toAbsolutePath().normalize();
        if (args[0].equals("generate")) {
            generate(dir, manifest);
        } else {
            System.exit(verify(dir, manifest));
        }
    }

    static void generate(Path dir, Path manifest) throws Exception {
        List<Path> files = listRegularFiles(dir, manifest);
        try (BufferedWriter writer = new BufferedWriter(
                new OutputStreamWriter(Files.newOutputStream(manifest), StandardCharsets.UTF_8))) {
            for (Path file : files) {
                String digest = sm3Hex(file);
                writer.write(digest + "  " + dir.relativize(file));
                writer.newLine();
            }
        }
        System.out.println("Manifest generated: " + manifest + " (" + files.size() + " files)");
    }

    static int verify(Path dir, Path manifest) throws Exception {
        List<String> lines = Files.readAllLines(manifest, StandardCharsets.UTF_8);
        int failed = 0;
        for (String line : lines) {
            if (line.isBlank()) {
                continue;
            }
            String expected = line.substring(0, 64);
            String relative = line.substring(66);
            Path file = dir.resolve(relative);
            if (!Files.isRegularFile(file)) {
                System.out.println(relative + ": FAILED (file missing)");
                failed++;
                continue;
            }
            String actual = sm3Hex(file);
            if (actual.equalsIgnoreCase(expected)) {
                System.out.println(relative + ": OK");
            } else {
                System.out.println(relative + ": FAILED");
                failed++;
            }
        }
        System.out.println(failed == 0 ? "ALL FILES OK" : failed + " FILE(S) FAILED");
        return failed == 0 ? 0 : 1;
    }

    static String sm3Hex(Path file) throws Exception {
        MessageDigest digest = MessageDigest.getInstance("SM3", "BC");
        try (InputStream in = Files.newInputStream(file)) {
            byte[] buffer = new byte[BUFFER_SIZE];
            int read;
            while ((read = in.read(buffer)) != -1) {
                digest.update(buffer, 0, read);
            }
        }
        return HexFormat.of().formatHex(digest.digest());
    }

    static List<Path> listRegularFiles(Path dir, Path manifest) throws Exception {
        try (Stream<Path> walk = Files.walk(dir)) {
            return walk
                    .filter(Files::isRegularFile)
                    .filter(p -> !p.toAbsolutePath().normalize().equals(manifest))
                    .sorted(Comparator.naturalOrder())
                    .collect(java.util.stream.Collectors.toCollection(ArrayList::new));
        }
    }
}
```

设计要点：

- 生成清单时把清单文件自身排除，避免「每次生成清单都把旧清单算进去」的自引用问题。
- 清单行固定格式：64 位 Hex + 两个空格 + 相对路径，解析时按固定位置切分，路径中允许包含空格。
- 文件缺失单独报 `FAILED (file missing)`，这也是完整性破坏的一种。

## ▶️ 执行命令

进入工程目录：

```bash
cd ~/gm-practices/gm-file-hash
```

```bash

    -Dexec.args="generate $HOME/gm-practices/data-dir $HOME/gm-practices/data-dir/MANIFEST.txt"
```

**2）首次校验**：

```bash
mvn -q compile exec:java -Dexec.mainClass=com.example.gm.ManifestTool \
    -Dexec.args="verify $HOME/gm-practices/data-dir $HOME/gm-practices/data-dir/MANIFEST.txt"
```

**3）篡改一个文件后再次校验**：

```bash
echo "tampered" >> ~/gm-practices/data-dir/sub/b.md
mvn compile exec:java -Dexec.mainClass=com.example.gm.ManifestTool \
    -Dexec.args="verify $HOME/gm-practices/data-dir $HOME/gm-practices/data-dir/MANIFEST.txt"
```

```text

```

```text

1 FILE(S) FAILED
```

此时进程退出码为 `1`，可被 CI 直接判定为失败。

> 你的 Hex 值取决于文件实际内容；`big.bin` 是随机生成的，值不同属正常。

## 🧯 常见失败与排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `StringIndexOutOfBoundsException` | 清单行被手工改坏，不足 66 字符 | 重新生成清单，不要手工编辑 |
| 所有文件都 `FAILED` | verify 的目录与 generate 时不是同一个根 | 确认 `<dir>` 为同一目录；路径用绝对路径 |
| 中文路径显示异常 | 终端/读取编码不是 UTF-8 | 清单统一 UTF-8 读写，终端使用 UTF-8 |
| 清单把自己也算进去了 | 未排除清单文件 | 保留代码中的 manifest 过滤逻辑 |
| 校验退出码总是 0 | 没有根据失败数返回退出码 | `verify` 返回 `failed==0?0:1` 并 `System.exit` |
| 路径含空格导致解析错乱 | 按空格 split 了路径 | 按固定位置 `substring(66)` 取路径 |
