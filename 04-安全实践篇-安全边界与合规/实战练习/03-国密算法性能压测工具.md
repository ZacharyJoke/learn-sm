# 练习 03 国密算法性能压测工具

> 用 JMH 亲手测出 SM3、SM4-GCM、SM2 签名的吞吐与单次耗时，建立「非对称少调用」的量化直觉，替代一切「听说很慢」。

## 目标

- 用 JMH 对三类操作做基准：SM3 摘要、SM4-GCM 加解密、SM2 签名（可选验签）。
- 同时输出吞吐量（ops/ms）与平均耗时（ms/op）。
- 根据本机数据换算「一次 SM2 签名 ≈ 加密多少数据」的直觉。
- 理解预热、fork、批处理对基准结果的影响。

## 前置

- JDK 17+、Maven；JMH 1.37（可替换更新稳定版），BC 1.78。
- 被测密钥在 `@Setup` 中用 `SecureRandom` 动态生成，工程中无任何硬编码密钥。

## 步骤

### 1. 编写基准类

`CryptoBenchmark.java`：

```java
package com.example.jmh;

import org.bouncycastle.crypto.AsymmetricCipherKeyPair;
import org.bouncycastle.crypto.digests.SM3Digest;
import org.bouncycastle.crypto.ec.CustomNamedCurves;
import org.bouncycastle.crypto.engines.SM4Engine;
import org.bouncycastle.crypto.generators.ECKeyPairGenerator;
import org.bouncycastle.crypto.modes.GCMBlockCipher;
import org.bouncycastle.crypto.params.AEADParameters;
import org.bouncycastle.crypto.params.ECDomainParameters;
import org.bouncycastle.crypto.params.ECKeyGenerationParameters;
import org.bouncycastle.crypto.params.ECPrivateKeyParameters;
import org.bouncycastle.crypto.params.ECPublicKeyParameters;
import org.bouncycastle.crypto.params.KeyParameter;
import org.bouncycastle.crypto.params.ParametersWithID;
import org.bouncycastle.crypto.params.ParametersWithRandom;
import org.bouncycastle.crypto.signers.SM2Signer;
import org.openjdk.jmh.annotations.Benchmark;
import org.openjdk.jmh.annotations.BenchmarkMode;
import org.openjdk.jmh.annotations.Fork;
import org.openjdk.jmh.annotations.Measurement;
import org.openjdk.jmh.annotations.Mode;
import org.openjdk.jmh.annotations.OutputTimeUnit;
import org.openjdk.jmh.annotations.Scope;
import org.openjdk.jmh.annotations.Setup;
import org.openjdk.jmh.annotations.State;
import org.openjdk.jmh.annotations.Warmup;
import org.openjdk.jmh.runner.Runner;
import org.openjdk.jmh.runner.RunnerException;
import org.openjdk.jmh.runner.options.Options;
import org.openjdk.jmh.runner.options.OptionsBuilder;
import org.openjdk.jmh.results.format.ResultFormatType;

import java.nio.ByteBuffer;
import java.security.SecureRandom;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.atomic.AtomicLong;

@BenchmarkMode({Mode.Throughput, Mode.AverageTime})
@OutputTimeUnit(TimeUnit.MILLISECONDS)
@Warmup(iterations = 3, time = 1)
@Measurement(iterations = 5, time = 1)
@Fork(1)
@State(Scope.Benchmark)
public class CryptoBenchmark {

    private static final int DATA_SIZE = 4096;
    private static final byte[] DEFAULT_ID = "1234567812345678".getBytes();

    private byte[] input;
    private byte[] sm4Key;
    private ECPrivateKeyParameters sm2PrivateKey;
    private ECPublicKeyParameters sm2PublicKey;
    private final AtomicLong ivCounter = new AtomicLong();

    @Setup
    public void setup() {
        SecureRandom random = new SecureRandom();
        input = new byte[DATA_SIZE];
        random.nextBytes(input);
        sm4Key = new byte[16];
        random.nextBytes(sm4Key);

        ECDomainParameters domain = sm2Domain();
        ECKeyPairGenerator generator = new ECKeyPairGenerator();
        generator.init(new ECKeyGenerationParameters(domain, random));
        AsymmetricCipherKeyPair pair = generator.generateKeyPair();
        sm2PrivateKey = (ECPrivateKeyParameters) pair.getPrivate();
        sm2PublicKey = (ECPublicKeyParameters) pair.getPublic();
    }

    @Benchmark
    public byte[] sm3Digest() {
        SM3Digest digest = new SM3Digest();
        digest.update(input, 0, input.length);
        byte[] hash = new byte[digest.getDigestSize()];
        digest.doFinal(hash, 0);
        return hash;
    }

    @Benchmark
    public byte[] sm4Gcm() throws Exception {
        GCMBlockCipher cipher = new GCMBlockCipher(new SM4Engine());
        byte[] iv = ByteBuffer.allocate(12).putLong(ivCounter.incrementAndGet()).array();
        cipher.init(true, new AEADParameters(new KeyParameter(sm4Key), 128, iv, null));
        byte[] output = new byte[cipher.getOutputSize(input.length)];
        int length = cipher.processBytes(input, 0, input.length, output, 0);
        cipher.doFinal(output, length);
        return output;
    }

    @Benchmark
    public byte[] sm2Sign() throws Exception {
        SM2Signer signer = new SM2Signer();
        signer.init(true, new ParametersWithID(
                new ParametersWithRandom(sm2PrivateKey, new SecureRandom()), DEFAULT_ID));
        signer.update(input, 0, 32);
        return signer.generateSignature();
    }

    public static void main(String[] args) throws RunnerException {
        Options options = new OptionsBuilder()
                .include(CryptoBenchmark.class.getSimpleName())
                .resultFormat(ResultFormatType.CSV)
                .result("benchmark.csv")
                .build();
        new Runner(options).run();
    }

    private static ECDomainParameters sm2Domain() {
        var parameters = CustomNamedCurves.getByName("sm2p256v1");
        return new ECDomainParameters(parameters.getCurve(), parameters.getG(),
                parameters.getN(), parameters.getH());
    }
}
```

要点说明：

- `sm2Sign` 只签前 32 字节，模拟「先 SM3 出摘要、再签摘要」的正确实践；不要在基准里用 SM2 签 4KB。
- SM4 的 IV 用递增计数器构造，既保证每次唯一（GCM 安全要求），又不把随机数生成成本混进加解密测量。
- 若想看验签成本，可仿照 `sm2Sign` 增加 `sm2Verify` 基准（预先在 `@Setup` 生成签名，基准中只做验签）。

## 验收标准

- 报告包含 3 个基准 × 2 种模式共 6 行结果，`Cnt = 5` 且无异常。
- 能用本机结果回答：SM2 签名平均耗时是 SM4-GCM 处理 4KB 的多少倍。
- 生成 `benchmark.csv`。
- 工程中无硬编码密钥，SM2 使用默认 ID。

### 结果记录与「柱状图」

把你的结果填进下表（示例），相对倍数按本机 `avgt` 相除得到：

| 操作（4KB / 签 32B） | 吞吐 ops/ms（示例） | 平均 ms/op（示例） | 相对 SM4-GCM 倍数 |
|---------------------|--------------------:|-------------------:|-------------------:|
| SM3 摘要 | 49 | 0.022 | 0.27× |
| SM4-GCM | 12 | 0.082 | 1× |
| SM2 签名 | 5.8 | 0.164 | 2× |

文本柱状图（按吞吐取对数意义不大，这里按平均耗时长短示意）：

```text
SM3 摘要   |
SM4-GCM    | █
SM2 签名   | ██
```

换算直觉（以示例值）：**做 1 次 SM2 签名的时间，SM4 大约能加密 2 × 4KB ≈ 8KB 数据**。单次差距看似不大，但差距随调用次数放大：SM2 若进入「每请求一次」的高频路径，成本快速累积；而它在信封中本可只在建连 / 包密钥时出现。请用你自己的实测倍数替换。

## 扩展思考

- **预热（Warmup）**：让 JIT 编译、内联与分支优化稳定后再计时；不预热结果偏差大。
- **fork**：每个 fork 是独立 JVM，避免上次运行的内存布局、类加载污染测量；生产对比建议 `forks(2)`。
- **批处理 `@BenchmarkBatchSize`**：只减少 JMH 计时方法的调用开销，不改变算法本身结论；不要用它「优化」业务。
- SM4 在真实业务用 GCM，基准也测 GCM；不要用 ECB 基准数据外推到生产。
- 若引入密码卡 / HSM，基准要把「调用方式（长连接 / 每次连接）」一并测量，网络与连接开销常常超过算法本身。
- 想测不同数据规模，可用 `@Param({"1024","4096","65536"})` 参数化，观察 SM4 随数据量的线性变化与 SM2 的基本不变。

## 失败排查

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 运行后没有生成 benchmark 类 | annotation processor 未生效 | 确认 `jmh-generator-annprocess` 已引入并重新 `clean` |
| 结果忽大忽小 | 机器在跑其他高负载程序 | 插电、关占用、增加 measurement 迭代次数 |
| SM2 基准比预期快很多 | 签名字节数不对 / JIT 消除了死代码 | 用 JMH 返回值消费结果（Blackhole），确认签 32B |
| GCM 抛 IV 重用相关错误 | IV 重复 | 使用计数器或随机 IV，保证同一密钥下唯一 |
| 找不到国密类 | BC 缺失 | 检查 `bcprov-jdk18on` 依赖 |
| exec:java 报插件缺失 | 未加插件 | 按上文配置 exec-maven-plugin |
