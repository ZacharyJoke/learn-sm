## 📐 案例标准结构

设计类案例统一采用：项目背景 → 业务目标 → 技术选型 → 系统架构 → 国密使用方式 → 数据流/签名流 → 接口设计 → 存储设计 → 安全风险 → 测试方案 → 部署方案 → 项目复盘 → 可交付物清单 → 验收标准。

故障类案例（06）采用七段式：

```text
🎯 案例背景 → 🚨 问题现象 → 🔍 排查过程 → 🧐 根因分析
→ ✅ 解决方案 → 📈 效果对比 → 📝 经验总结（Action Items）
```

---

## 🧭 三种学习方式

- **初学者跟做**：按案例文档逐步复现，重点理解每个设计点的原因。
- **进阶者先思考**：先只看背景与目标，自行画架构，再对照文档找差距。
- **高级者迁移**：抽取案例的决策框架，迁移到自己工作中的真实项目。

## ✅ 阶段考核标准

- [ ] 6 个案例全部学习，每个产出一页个人复盘笔记
- [ ] 能脱稿画出至少 3 个案例的架构图与数据流
- [ ] 能回答每个案例中「为什么不用另一个算法/模式」
- [ ] 按七段式独立整理 1 个自己工作中的真实案例（脱敏）
- [ ] 从案例中沉淀至少 10 条可复用检查项

## 📝 贡献与沉淀指南
