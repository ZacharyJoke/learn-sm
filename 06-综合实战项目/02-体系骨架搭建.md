## 3. pom.xml 关键片段

### 3.1 父 POM 与工程坐标

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.4.6</version>
    <relativePath/>
</parent>

<groupId>com.gmcrypto</groupId>
<artifactId>gm-crypto-suite</artifactId>
<version>1.0.0</version>
<name>gm-crypto-suite</name>
<description>SM2/SM3/SM4 国密能力组件工程</description>
```

### 3.2 版本属性

```xml
<properties>
    <java.version>17</java.version>
    <bc.version>1.84</bc.version>
</properties>
```

要点：

- `java.version=17` 由 Spring Boot 父 POM 映射为 `maven.compiler.release=17`，即使用 JDK 21 执行构建，字节码与 API 仍被约束在 17；
- `bc.version` 单独显式声明，密码库版本必须可一处审视、一处升级，禁止依赖传递时的隐式版本。

### 3.3 依赖

```xml
<dependencies>
    <dependency>
        <groupId>org.bouncycastle</groupId>
        <artifactId>bcprov-jdk18on</artifactId>
        <version>${bc.version}</version>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
```

选型说明：`bcprov-jdk18on` 是面向 JDK 1.8+ 的 Provider 包（命名中的 `18on` 不要求 JDK 18），SM2/SM3/SM4 支持完整；只引 Provider 不引 `bcpkix`，保持依赖面最小。

### 3.4 打包插件

```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
        </plugin>
    </plugins>
</build>
```

`mvn package` 直接产出可执行 fat jar：`target/gm-crypto-suite-1.0.0.jar`。

## 4. BouncyCastle Provider 初始化

工程没有自定义 `SecurityConfig`，Provider 注册放在各算法工具类的静态初始化块中：

```java
public final class Sm3Support {

    static {
        Security.addProvider(new BouncyCastleProvider());
    }
    // ...
}
```

`Sm3Support`、`Sm4Support`、`Sm2Support` 均采用同一写法。设计要点：

- `Security.addProvider` 对「同类 Provider 重复注册」是幂等语义：重复添加只会得到同一 Provider 的注册位，不会产生功能冲突；类加载时执行，早于任何算法调用；
- 每次取算法实例时显式传入 Provider，杜绝「依赖机器上 JCE 注册顺序」的不确定性：

```java
MessageDigest.getInstance("SM3", new BouncyCastleProvider());
Cipher.getInstance("SM4/GCM/NoPadding", new BouncyCastleProvider());
Signature.getInstance("SM3withSM2", new BouncyCastleProvider());
```

- 注册与取用并存，即使 JVM 中已存在其他 BC 版本，本工程调用仍绑定到自己 classpath 上的 `1.84` Provider；
- 工具类声明为 `final` 且构造器 `private`，只暴露静态方法，不持有可变状态。

## 5. application.yml 说明

真实配置全文：

```yaml
spring:
  application:
    name: gm-crypto-suite

gm:
  keys:
    dir: data/keys
  signature:
    timestamp-skew-seconds: 300

logging:
  level:
    com.gmcrypto.suite: INFO
```

逐项说明：

| 配置 | 含义 | 备注 |
|------|------|------|
| `spring.application.name` | 应用名 | 日志 / 注册中心识别用 |
| `gm.keys.dir` | 密钥目录（**预留**） | 当前 `LocalKeyVersionStore` 为内存实现，不读取该值；生产持久化落地时启用 |
| `gm.signature.timestamp-skew-seconds` | 签名时间戳允许偏移 | 默认 300 秒；由 `WebConfig` 的 `@Value` 注入，代码侧同样带默认值 300 |
| `logging.level.com.gmcrypto.suite` | 工程日志级别 | 默认 INFO，排障时可临时调 DEBUG |

**密钥不写明文**是配置红线：

- yml 中只有目录与时间窗口，没有任何对称密钥、私钥或口令字段；
- 演示收件人密钥由 `SuiteBeanConfig` 在启动时通过 `KeyVersionStore.register("SM2")` 现场生成，不落盘；
- 生产环境密钥来源应替换为环境变量 / KMS / HSM，配置文件只保留引用（keyId），不保留素材。

## 6. 启动步骤

### 6.1 前置条件

- JDK 17 或 21，确认 `java -version`；
- Maven 3.6+（或使用 IDE 内置 Maven）；
- 默认占用 8080 端口，确保未被占用。

### 6.2 方式一：Maven 直接启动

```bash
cd project/gm-crypto-suite
mvn spring-boot:run
```

### 6.3 方式二：打包后以 jar 启动

```bash
mvn clean package
java -jar target/gm-crypto-suite-1.0.0.jar
```

### 6.4 快速验证

信封演示接口不在签名保护路径内，可直接调用：

```bash
curl -s -X POST http://localhost:8080/api/demo/envelope \
  -H 'Content-Type: application/json' \
  -d '{"plaintext":"hello gm"}'
```

预期返回（`recipientKeyId` 每次启动不同）：

```json
{"recipientKeyId":"<UUID>","digest":"<SM3 十六进制>","opened":"hello gm"}
```

### 6.5 审计命令行入口

以非 Web 方式启动并对指定源码文件执行静态审计，输出告警后进程退出：

```bash
java -jar target/gm-crypto-suite-1.0.0.jar \
  --spring.main.web-application-type=none \
  --audit=src/main/java/com/gmcrypto/suite/sm4/Sm4Support.java
```

不带 `--audit` 参数时，`AuditCliRunner` 立即返回，不影响正常启动。

- 出现 `NoSuchAlgorithmException: SM3` —— BC 依赖未进入 classpath 或版本被覆盖，执行 `mvn dependency:tree | grep bouncycastle` 核对；
