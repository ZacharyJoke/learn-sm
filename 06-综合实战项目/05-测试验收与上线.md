# 05 · 测试验收与上线

> 本篇给出测试金字塔与 23 个真实用例、CI 流水线、发布 / 回滚方案、上线 checklist 与逐条验收表。
> 原则：标准向量不过不发布，测试不全绿不发布，审计 HIGH 不清零不发布。

---

## 1. 测试金字塔

| 层次 | 形态 | 用例数 | 覆盖内容 |
|------|------|--------|----------|
| 单元测试 | 纯 JUnit 5，直接调用静态方法 / `new` 服务对象，不启动 Spring | 19 | SM3×3、SM4×4、SM2×5、信封×4、密钥×2、审计×1 |
| 集成测试 | `@SpringBootTest` + `@AutoConfigureMockMvc`，真实 Filter / 拦截器链 | 4 | 签名接口合法、过期、重放、错签 |
| 合计 | — | **23** | 全绿（实测：JDK 21 执行，17 字节码基线） |

金字塔取向：算法正确性由大量不起容器的快速单托底，只有「请求体缓存 → 拦截器 → Controller」这条链必须用集成测试证明组装无误。

## 2. 真实用例表（23 个）

### 2.1 SM3（`Sm3SupportTest`，3 个）

| 用例 | 断言 |
|------|------|
| `emptyVector` | `SM3("") = 1ab21d8355cfa17f8e61194831e81a8f22bec8c728fefb747ed035eb5082aa2b` |
| `abcVector` | `SM3("abc") = 66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0` |
| `hmacChangesWithKey` | 不同 key 的 HMAC-SM3 结果不相等 |

### 2.2 SM4（`Sm4SupportTest`，4 个）

| 用例 | 断言 |
|------|------|
| `ecbStandardVector` | key=`0123456789abcdeffedcba9876543210`、明文同值 → `681edf34d206965e86b3e94f536e4246`（单块 ECB 标准向量） |
| `gcmRoundTrip` | AAD=`key-v1` 时 GCM 往返明文一致 |
| `gcmTamperDetected` | 翻转密文首字节后解密抛 `GmCryptoException` |
| `cbcRoundTrip` | CBC 往返 100 字节填充报文一致 |

### 2.3 SM2（`Sm2SupportTest`，5 个）

| 用例 | 断言 |
|------|------|
| `signAndVerify` | 默认 userId 下签名可验通过 |
| `tamperedMessageRejected` | 原文被替换后验签返回 false |
| `mismatchedUserIdRejected` | 签名用默认 userId、验签用 `8765432187654321` → false |
| `encryptAndDecrypt` | C1C3C2 短数据往返一致 |
| `pemRoundTrip` | 公私钥 PEM 重新加载后仍可签名验签 |

### 2.4 信封（`EnvelopeServiceTest`，4 个）

| 用例 | 断言 |
|------|------|
| `sealAndOpen` | `seal` → `open` 还原「信封正文 confidential」 |
| `tamperedCiphertextRejected` | 翻转 ciphertext 首字节，`open` 抛异常（GCM tag 失败） |
| `tamperedEncryptedKeyRejected` | 翻转 encryptedKey 字节，SM2 解密阶段抛异常 |
| `tamperedDigestRejected` | digest 改为 64 个 `0` → 错误码 `INTEGRITY_CHECK_FAILED` |

### 2.5 密钥版本（`KeyVersionStoreTest`，2 个）

| 用例 | 断言 |
|------|------|
| `registerGetAndRotate` | 注册即 ACTIVE；`markStatus(ROTATED)` 后状态为 ROTATED |
| `missingKeyThrows` | 查询不存在 id 抛 `GmCryptoException`（`KEY_NOT_FOUND`） |

### 2.6 Web 签名（`SignVerifyInterceptorTest`，4 个）

| 用例 | 断言 |
|------|------|
| `validSignatureAccepted` | 正确四头 + 签名 → 200 |
| `expiredTimestampRejected` | 时间戳回退 1 小时 → 400 |
| `replayRejected` | 同 nonce 第一次 200、第二次 409 |
| `wrongSignatureRejected` | 签名替换为 64 字节 `00` → 401 |

### 2.7 审计（`CryptoAuditorTest`，1 个）

| 用例 | 断言 |
|------|------|
| `detectsRules` | 对含 ECB、`new Random()`、32 位 Hex 的临时代码，命中 `GM-ECB`、`GM-WEAK-RANDOM` 且 findings ≥ 3 |

标准向量断言示例（真实写法）：

```java
assertEquals("1ab21d8355cfa17f8e61194831e81a8f22bec8c728fefb747ed035eb5082aa2b",
        Codec.toHex(Sm3Support.digest(new byte[0])));
```

## 4. CI 流水线（通用 yaml 占位）

阶段顺序：**编译 → 测试 → 审计 → 打包**。

```yaml
name: gm-crypto-suite-ci

on:
  push:
    branches: [main]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装 JDK 17
        uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'
          cache: maven

      - name: 编译
        run: mvn -B -ntp clean compile

      - name: 单元与集成测试
        run: mvn -B -ntp test

      - name: 打包（供审计步骤使用）
        run: mvn -B -ntp package -DskipTests

      - name: 静态密码审计
        run: |
          java -jar target/gm-crypto-suite-1.0.0.jar \
            --spring.main.web-application-type=none \
            --audit=src/main/java | tee audit.log

      - name: HIGH 命中即失败（门禁占位）
        run: |
          if grep -E 'GM-ECB|GM-WEAK-RANDOM|GM-EMBEDDED-PRIVATE-KEY' audit.log; then
            echo "存在 HIGH 级密码风险" && exit 1
          fi

      - name: 正式打包
        run: mvn -B -ntp clean package

      - name: 归档制品
        uses: actions/upload-artifact@v4
        with:
          name: gm-crypto-suite-jar
          path: target/gm-crypto-suite-1.0.0.jar
```

门禁说明：标准向量中的公开测试值（如 `0123456789abcdeffedcba9876543210`）位于 test 目录，审计目标限定 `src/main/java`，避免误报；如 Jenkins/GitLab CI，平移各 `run` 为对应 step 即可。

## 5. 发布与回滚

### 5.1 发布物与配置

- 制品：`gm-crypto-suite-1.0.0.jar`（fat jar）；
- 配置外置：部署目录放置 `application.yml`（或用环境变量 / 配置中心），jar 内配置仅为默认值；
- 启动：`java -jar gm-crypto-suite-1.0.0.jar --spring.config.additional-location=file:./application.yml`。

### 5.2 发布方式

- 推荐蓝绿 / 滚动发布：新版本先接小流量，验 200 成功率与验签失败率后再全量；
- 上线后冒烟：`/api/demo/envelope` 往返、`/api/signed/echo` 用有效签名头验证一次；
- 观测窗口：关注验签 401、重放 409、500 错误率与操作延迟。

### 5.3 回滚方案

| 情形 | 动作 |
|------|------|
| 新版本缺陷 / 错误率升高 | 流量切回上一版本 jar 与对应配置，保留现场日志 |
| 配置错误 | 回滚 `application.yml`，无需更换制品 |
| 密钥相关 | 生产 KMS 中**保留旧版本密钥**，保证回滚后仍可解开历史信封；内存演示版无历史数据，可直接重建 |

兼容性要点：信封自带 `version=1`，回滚旧程序处理新信封前须确认版本契约；本期不跨版本，故回滚安全。

## 6. 上线 Checklist

**质量门禁**

- [ ] JDK 17 构建（CI 中 `java-version: '17'`），非本地口头确认
- [ ] `mvn test` 23 用例全绿，标准向量断言可见
- [ ] 审计 `src/main/java` 无 HIGH 命中；MEDIUM 有处置结论
- [ ] `mvn clean package` 成功，jar 可独立启动

**安全**

- [ ] yml / 环境变量中无明文密钥与私钥
- [ ] 时间戳窗口、nonce TTL 按生产评估（默认 300 秒）
- [ ] 日志抽查：无明文、无密钥、最多到短指纹
- [ ] 异常响应抽查：仅返回 `errorCode`

**运行**

- [ ] 端口、健康检查、启动参数确认
- [ ] 外置配置与启动脚本就位，日志可采集
- [ ] 冒烟用例（信封 + 签名接口）执行通过
- [ ] 回滚版本与旧配置已保留、可一键切回

## 7. 验收逐条表

| 验收项 | 标准 | 证据 |
|--------|------|------|
| 算法正确性 | SM3 空 / `abc`、SM4-ECB 向量断言通过 | 对应 3+1 用例 |
| 对称加密 | GCM（AAD）往返、篡改必拒；CBC 往返 | SM4×4 |
| 非对称能力 | 签名验签、错 userId 拒绝、加解密、PEM 往返 | SM2×5 |
| 数字信封 | 正常往返；密文 / 密钥 / 摘要三类篡改分别被拒 | 信封×4 |
| 密钥生命周期 | 注册 / 查询 / 状态流转、缺失报错 | 密钥×2 |
| 接口安全 | 合法放行、过期 / 错签 / 重放分别拒绝 | Web×4 |
| 审计能力 | 5 规则样例命中 ≥ 3，定位到行 | 审计×1 |
| 可交付 | jar 可启动、接口冒烟通过、回滚路径明确 | 发布记录 |
| 合规姿态 | 无硬编码密钥、日志脱敏、异常不泄密 | 抽查记录 |
