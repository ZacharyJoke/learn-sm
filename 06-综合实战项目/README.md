# 第六阶段：综合实战项目 · gm-crypto-suite

> 🏗️ 用一个可运行的企业级工程，把全部能力焊死在作品里。

---

## 🌟 项目愿景与目标

构建一个基于 Spring Boot 3 + BouncyCastle 的国密能力组件工程 `gm-crypto-suite`，作为团队 `crypto-common`/SDK 的起点：开箱即用、安全默认、测试完备、可审计。

**能力目标：**

- SM2 密钥、签名验签、加解密；SM3/HMAC-SM3；SM4（CBC/CTR/GCM）
- SM2+SM3+SM4 数字信封；接口签名验签拦截器（防重放）
- 密钥版本管理；静态审计扫描工具
- 标准算法测试向量校验、JUnit 5 全量测试

---

## 📋 需求清单

### 业务/能力需求

- 提供统一门面 `CryptoFacade`，屏蔽底层算法复杂度
- 提供可插拔的接口签名验签 Spring 组件（注解 + 拦截器）
- 提供信封的封包/拆包 API 与 JSON 序列化结构

### 非功能/约束需求

- JDK 17 基线（工程在 JDK 21 实测）；密钥零硬编码
- 加解密往返 P99 延迟、SM4 吞吐有基准数据
- 全量日志脱敏；异常不泄露密钥与明文
- 标准向量测试必须通过后方可打包发布

## 🧭 选型矩阵

| 维度 | 选型 | 理由 |
|------|------|------|
| 运行框架 | Spring Boot 3.x | Java 17+ 生态、Web 拦截器能力 |
| 密码库 | BouncyCastle `bcprov-jdk18on` | 国密支持最全、开源可审计 |
| 构建 | Maven | 目标读者主流栈 |
| 测试 | JUnit 5 | 与 Spring Boot 3 对齐 |
| 基准 | JMH（可选 profile） | 可信性能数据 |

## ⚠️ 风险评估与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| BC 版本 API 差异 | 编译/行为变化 | 版本锁定在 `pom.xml`，变更走测试 |
| 密钥泄露 | 全局失守 | KMS/环境注入 + 审计 + 零日志 |
| 密文格式互通 | 与对端系统对接失败 | 统一 C1C3C2、编码与信封 JSON 契约 |
| 性能不达标 | 业务超时 | JMH 定位、SM4 批量 + SM2 少用 |
