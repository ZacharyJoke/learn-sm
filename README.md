# 国密算法高手知识体系知识库

> 面向有 Java 后端经验、密码学基础薄弱的工程师，从零基础到能独立主导国密改造的高手训练体系——可自学、可培训、可工程复用。

---

## 关于本知识体系

本知识体系面向 **Java 后端工程师 / 架构师 / 安全合规改造参与者**，帮助你从「只会调加密工具类、说不清原理」成长为「懂原理、能落地、通合规、可主导国密改造」的安全工程高手。

**你的起点画像：**

- ✅ 当前基础：1 年以上 Java 后端经验，熟悉 Spring Boot、Maven、HTTP，密码学仅停留在「听过 AES/RSA/MD5」
- ✅ 重点关注：SM2/SM3/SM4 工程落地、国密改造、密评合规、接口签名与密钥管理
- ✅ 期望产出：可运行的国密工具工程、6 个完整项目案例、19 个实战练习产出、可复用的审计清单与模板

**学完你将具备：**

- 能向团队讲清每个国密算法「是什么、为什么安全、什么时候用」
- 能基于 BouncyCastle 写出规范、安全、可测试的 SM2/SM3/SM4 代码
- 能设计数字信封、接口签名验签、密钥管理、国密 TLS 改造方案
- 能主导或深度参与金融/政务/通信场景的国密改造与密评迎检

## 🎯 六阶段能力概述

### 第一阶段：入门篇 · 国密全景认知
> 先见森林，后见树木——用一周建立不跑偏的全局认知。

- 说清「国密」的标准体系（GB/T、GM/T）、主管机构与合规语境
- 建立对称/非对称/哈希/流密码/标识密码五大原语的概念地图
- 掌握 SM1/SM2/SM3/SM4/SM7/SM9/ZUC 的一句话定位与相互关系
- 理解国密改造的驱动力：等保、密评（商用密码应用安全性评估）、行业监管、自主可控

[→ 进入第一阶段](./01-入门篇-国密全景认知/README.md)

---

### 第二阶段：原理篇 · 算法核心机制
> 高手与「调包侠」的分水岭：知其所以然，才知道安全边界在哪。

- SM2：椭圆曲线点运算、签名（SM3withSM2）、公钥加密（C1C3C2）、密钥交换
- SM3：Merkle–Damgård 结构、消息扩展、压缩函数、256 位摘要与抗碰撞
- SM4：32 轮非平衡 Feistel、S 盒、轮密钥扩展、分组密码工作模式
- SM9：双线性配对与标识密码（IBC）；ZUC：LFSR 流密码；SM1/SM7 的公开边界

[→ 进入第二阶段](./02-原理篇-算法核心机制/README.md)

---

### 第三阶段：工程实现篇 · Java 代码落地

- 库选型：BouncyCastle、GmSSL、OpenSSL 国密模块、商用密码 SDK 的取舍
- SM2 密钥对生成、签名验签、加解密；SM3 摘要、文件校验、HMAC-SM3
- SM4 的 ECB/CBC/CTR/GCM 模式与填充、IV/Nonce 的安全要求
- 编码规范（Hex/Base64/字节数组）、SecureRandom、异常体系、JUnit 5 测试设计

[→ 进入第三阶段](./03-工程实现篇-Java代码落地/README.md)

- [ ] JDK 17+（本体系工程实际在 JDK 21 上验证，17 为目标基线）

## 💡 学习建议

1. **不要跳过第一、二阶段直接抄代码**：原理决定了你能不能识别错误用法（如固定 IV、ECB 模式）。
2. **每个代码示例亲手跑一遍并改参数观察**：改 IV、改模式、篡改密文，观察行为差异。
3. **用标准测试向量校准实现**：SM3/SM4 有公开标准答例，跑不对照例即实现有误。
4. **区分「公开标准」与「不可确认细节」**：SM1/SM7 算法不公开，不臆测内部结构，只谈部署形态与边界。
5. **把第六阶段工程当团队资产**：直接演化为你团队的 `crypto-common` 组件或 SDK。
6. **合规视角贯穿始终**：技术方案最终要回答「能不能过密评」，第四阶段给出依据。
