# 国密算法速查表（Java 工程师版）

> 适用对象：使用 Java / BouncyCastle 的后端工程师。
> 运行环境：JDK 8+、`bcprov-jdk18on:1.84`。
> 约定：密钥/IV 均以字节为单位；Hex 为小写十六进制；表中标注「以标准文本为准」处请查阅正式标准。

## 一、七大算法总表

| 算法 | 类型 | 核心参数 | 标准号 | OID | BouncyCastle 名称 | 典型用途 |
|------|------|----------|--------|-----|-------------------|----------|
| SM1 | 分组对称密码（算法不公开） | 分组 128bit、密钥 128bit（以批准产品实现为准） | 不公开，仅在密码产品/芯片中实现 | 不公开 | 不支持（需 SDF/密码芯片） | 社保卡、门禁、加密 USBKey、行业终端 |
| SM2 | 椭圆曲线公钥密码（签名/密钥交换/公钥加密） | 私钥 256bit；曲线 sm2p256v1；摘要用 SM3；默认用户 ID `1234567812345678` | GB/T 32918、GM/T 0003 | 签名 `1.2.156.10197.1.501`；公钥加密 `1.2.156.10197.1.301` | `KeyPairGenerator "EC"` + `ECNamedCurveGenParameterSpec("sm2p256v1")`；`Signature "SM3withSM2"`；`Cipher "SM2"` | 数字签名、电子证书、密钥协商、公钥加密 |
| SM3 | 密码杂凑算法 | 输出 256bit；消息分组 512bit；Merkle–Damgård 结构 | GB/T 32905、GM/T 0004 | `1.2.156.10197.1.401` | `MessageDigest "SM3"`；`Mac "HMAC-SM3"` | 数据摘要、HMAC、签名摘要、完整性校验 |
| SM4 | 分组对称密码 | 密钥 128bit、分组 128bit、32轮、非平衡 Feistel | GB/T 32907、GM/T 0002 | `1.2.156.10197.1.104` | `KeyGenerator "SM4"`；`Cipher "SM4/ECB\|CBC\|GCM/..."` | 业务数据加密、VPN、磁盘/文件加密 |
| SM7 | 分组对称密码（算法不公开） | 分组 128bit、密钥 128bit（以批准产品实现为准） | 不公开 | 不公开 | 不支持 | 非接触式 IC 卡、门禁卡、电子票证 |
| SM9 | 基于标识的密码（IBC，签名/加密/密钥交换/封装） | 用户标识即公钥；KGC 生成私钥；256bit 安全强度 | GM/T 0044（第1~5部分） | OID 以 GM/T 0044 标准文本为准 | BC 提供 SM9 低层级 API（无统一 JCE 名称，以所用 BC 版本说明为准） | 身份即公钥场景：邮件、政务、物联网、跨域认证 |
| ZUC（祖冲之） | 序列密码（流密码） | 密钥 128bit + IV 128bit；含 3GPP EEA3 加密、EIA3 完整性 | GM/T 0001；3GPP TS 35.221/35.222 | 无常用 OID | BC 低层级 `ZUC128Engine` 等（无统一 JCE 名称，以版本为准） | 4G/5G 空口信令与数据加密（EEA3/EIA3） |

### OID 弧速记

- 国密 OID 统一在弧 `1.2.156.10197` 下。
- 常用：SM3 `1.2.156.10197.1.401`；SM4 `1.2.156.10197.1.104`；SM2 签名 `1.2.156.10197.1.501`；SM2 公钥加密 `1.2.156.10197.1.301`。
- SM2 密钥交换、SM9 各部分等其余 OID 以标准文本为准，不要凭记忆硬编码。

## 二、BouncyCastle 一行流代码

Maven 依赖：

```xml
<dependency>
    <groupId>org.bouncycastle</groupId>
    <artifactId>bcprov-jdk18on</artifactId>
    <version>1.84</version>
</dependency>
```

注册一次即可（建议在应用启动时执行）：

```java
Security.addProvider(new org.bouncycastle.jce.provider.BouncyCastleProvider());
```

```java
// 1) SM3 摘要：SM3("abc") = 66c7f0f4...ba8e0
byte[] hash = MessageDigest.getInstance("SM3", "BC")
        .digest("abc".getBytes(StandardCharsets.UTF_8));

// 2) HMAC-SM3
Mac mac = Mac.getInstance("HMAC-SM3", "BC");
mac.init(new SecretKeySpec(key16, "HMAC-SM3"));
byte[] tag = mac.doFinal(data);

// 3) SM2 密钥对（曲线 sm2p256v1）
KeyPairGenerator kpg = KeyPairGenerator.getInstance("EC", "BC");
kpg.initialize(new ECNamedCurveGenParameterSpec("sm2p256v1"), new SecureRandom());
KeyPair kp = kpg.generateKeyPair();

// 4) SM2 签名（必须设置用户 ID，双方一致；默认 1234567812345678）
Signature sig = Signature.getInstance("SM3withSM2", "BC");
sig.setParameter(new org.bouncycastle.jcajce.spec.SM2ParameterSpec(
        "1234567812345678".getBytes(StandardCharsets.UTF_8)));
sig.initSign(kp.getPrivate());
sig.update(data);
byte[] signDer = sig.sign();

// 5) SM2 验签
Signature verifier = Signature.getInstance("SM3withSM2", "BC");
verifier.setParameter(new org.bouncycastle.jcajce.spec.SM2ParameterSpec(
        "1234567812345678".getBytes(StandardCharsets.UTF_8)));
verifier.initVerify(kp.getPublic());
verifier.update(data);
boolean ok = verifier.verify(signDer);

// 6) SM2 公钥加密 / 解密（BC 默认输出 GM/T 0009 的 C1C3C2 ASN.1 结构）
Cipher sm2 = Cipher.getInstance("SM2", "BC");
sm2.init(Cipher.ENCRYPT_MODE, kp.getPublic());
byte[] ct = sm2.doFinal(plain);
sm2.init(Cipher.DECRYPT_MODE, kp.getPrivate());
byte[] pt = sm2.doFinal(ct);

// 7) SM4 密钥（128bit）
KeyGenerator kg = KeyGenerator.getInstance("SM4", "BC");
kg.init(128);
SecretKey sm4Key = kg.generateKey();
// 或用已有字节：new SecretKeySpec(raw16, "SM4")

// 8) SM4/CBC/PKCS5Padding（IV 16 字节，每次随机）
Cipher cbc = Cipher.getInstance("SM4/CBC/PKCS5Padding", "BC");
cbc.init(Cipher.ENCRYPT_MODE, new SecretKeySpec(raw16, "SM4"),
        new IvParameterSpec(iv16));
byte[] cbcCt = cbc.doFinal(data);

// 9) SM4/GCM/NoPadding（推荐；tag 128bit，nonce 建议 12 字节且每次唯一）
Cipher gcm = Cipher.getInstance("SM4/GCM/NoPadding", "BC");
gcm.init(Cipher.ENCRYPT_MODE, sm4Key, new GCMParameterSpec(128, nonce12));
gcm.updateAAD(aad);                 // 无 AAD 可省略
byte[] gcmCt = gcm.doFinal(data);  // 输出含末尾 16 字节 tag
```

标准向量自检：

```text
SM3("")   = 1ab21d8355cfa17f8e61194831e81a8f22bec8c728fefb747ed035eb5082aa2b
SM3("abc") = 66c7f0f462eeedd9d1f2d46bdc10e4e24167c4875cf2f7a2297da02b8f4ba8e0
SM4/ECB key=0123456789abcdeffedcba9876543210, plain=同key
          => 681edf34d206965e86b3e94f536e4246
```

## 三、OpenSSL 常用命令

> 需 OpenSSL 1.1.1+（3.x 对国密支持更完整）或 GmSSL；不同发行版支持的子命令略有差异。

```bash
# SM3 摘要
openssl dgst -sm3 file.bin
printf 'abc' | openssl dgst -sm3

# SM2 私钥 / 自签证书（-sm3 指定签名摘要）
openssl ecparam -name SM2 -genkey -noout -out sm2.key
openssl req -new -key sm2.key -sm3 -subj "/CN=demo/O=org" -out sm2.csr
openssl req -x509 -key sm2.key -sm3 -days 365 -subj "/CN=demo" -out sm2.crt
openssl ec -in sm2.key -text -noout          # 查看私钥与曲线参数
openssl x509 -in sm2.crt -text -noout        # 查看证书

# SM4 加解密（K/iv 为 Hex；-a 输出 Base64）
openssl enc -sm4-cbc -e -in in.txt -out out.enc -K 0123...ff -iv 0011...ee
openssl enc -sm4-cbc -d -in out.enc -K 0123...ff -iv 0011...ee
openssl enc -sm4-ecb -e -a -in in.txt -K 0123...ff

# 随机数（密钥/IV 生成）
openssl rand -hex 16
```

SM2 公钥加密/解密的命令行在原生 OpenSSL 各版本间不统一（GmSSL 提供 `sm2utl` 等扩展），跨工具互通优先用标准密文文件做联调，详见 `06-常见问题FAQ.md`。

## 四、字节长度速查

| 项目 | 长度 | 说明 |
|------|------|------|
| SM2 私钥 | 32 字节 | 大整数，需定长补零 |
| SM2 公钥（未压缩点） | 65 字节 | `04` + X(32) + Y(32) |
| SM2 坐标 X/Y | 各 32 字节 | 大端表示 |
| SM2 默认用户 ID | 16 字节 | ASCII 字符串 `1234567812345678` |
| SM3 输出 | 32 字节（256bit） | 不可截断后当安全强度使用 |
| SM3 分组 | 64 字节（512bit） | |
| SM4 密钥 / 分组 / IV | 各 16 字节（128bit） | IV 必须每次唯一，无需保密 |
| SM4 GCM nonce | 建议 12 字节 | 96bit 为推荐值；tag 常取 16 字节 |
| SM2 密文 C1C3C2 | 65 + 32 + 明文长度 | C1 为未压缩点，C3 为 SM3，C2 与明文等长 |
| SM2 签名 raw | 64 字节 | r(32) ‖ s(32)，需定长 |
| SM2 签名 DER | 约 70~72 字节 | ASN.1 SEQUENCE{r,s}，长度随前导零变化 |
| ZUC 密钥 / IV | 各 16 字节 | GM/T 0001 |

## 五、密文与证书格式

### SM2 密文（GM/T 0009，C1C3C2）

```text
ASN.1: SEQUENCE {
    C1  椭圆曲线点（未压缩形式 04 ‖ X ‖ Y，共 65 字节）
    C3  SM3 摘要（32 字节）
    C2  与明文等长的密文
}
```

- 国标现行顺序为 **C1C3C2**；旧系统/部分早期库使用 C1C2C3，互通时必须调整字段顺序。
- 04 是椭圆曲线未压缩点标识，不是密文版本号。

### SM2 签名

- DER：`SEQUENCE { r INTEGER, s INTEGER }`，JCE `Signature` 输出格式。
- raw：`r ‖ s`，各 32 字节定长，常用于接口传输；与对端约定后互转。

### SM2 数字证书（GM/T 0015）

- 基于 SM2/SM3 的证书格式，国密体系常用「双证书」：签名证书 + 加密证书（加密证书私钥常由密钥管理系统托管）。
- 证书中签名算法 OID 为 `1.2.156.10197.1.501`（SM3withSM2）。

## 六、常见报错 — 原因 — 处理

| 报错/现象 | 原因 | 处理 |
|-----------|------|------|
| `NoSuchAlgorithmException: SM3` | 未注册 BC 或缺少依赖 | 启动时 `Security.addProvider(new BouncyCastleProvider())`；引入 bcprov 依赖 |
| `NoSuchAlgorithmException: HMAC-SM3` | BC 版本过低 | 升级到 1.70+（本文基于 1.84） |
| `InvalidKeyException: Illegal key size` | 老版本 JDK 策略限制或密钥长度错误 | JDK 8u161+ 默认无限制；同时核对 SM4 密钥是否 16 字节 |
| SM2 加解密报 key 类型错误 | 用 SUN 的 EC Key 直接喂给 BC SM2 Cipher | 用 BC 生成密钥，或用 `ECUtil`/BouncyCastle 工具将 Key 转为 BC 类型 |
| SM2 验签恒为 false | 用户 ID 不一致；数据拼接顺序不同；DER/raw 混用 | 统一 ID 与待签名报文（ZA 计算输入）；统一签名编码 |
| 跨语言 SM2 密文解不开 | C1C3C2 与 C1C2C3 顺序不同；04 前缀被剥 | 按 GM/T 0009 对齐顺序与前缀，抓标准向量互测 |
| `BadPaddingException`（GCM） | tag 校验失败：key/nonce/AAD/tag 任一不符 | 核对密钥、nonce、AAD 拼接、tag 位置（BC tag 在密文末尾） |
| SM4 跨语言解密乱码 | 填充不一致：PKCS5/PKCS7/NoPadding；模式不一致 | 统一模式与填充（推荐 CBC/PKCS5Padding 或 GCM/NoPadding） |
| `IllegalBlockSizeException`（NoPadding） | 明文不是 16 字节整数倍 | 改用带填充模式，或业务层补齐并约定 |
| `InvalidAlgorithmParameterException: IV buffer too short` | IV 不是 16 字节 | SM4 CBC/ECB? IV 固定 16 字节；GCM nonce 建议 12 字节 |
| 服务启动偶发卡顿数十秒 | `SecureRandom` 使用 `/dev/random` 阻塞 | 用 `-Djava.security.egd=file:/dev/./urandom` 或显式 `getInstanceStrong()` 评估后选型 |
| `ClassNotFoundException: org.bouncycastle...` | 依赖未打包/多版本冲突 | 检查 fat jar、排除重复 bcprov 版本 |

## 七、使用红线

- 禁止用 SM3 直接存口令：口令存储必须用加盐慢哈希（PBKDF2/Argon2/bcrypt 等）。
- 禁止 ECB 模式加密多块业务数据；IV/nonce 固定等同失效，必须每次随机唯一。
- 禁止自研密码算法或在业务代码中硬编码密钥；密钥走 KMS/配置中心加密管理。
- SM1/SM7 算法不公开，任何「软件实现 SM1/SM7」的说法都应警惕，通过合规密码产品使用。
