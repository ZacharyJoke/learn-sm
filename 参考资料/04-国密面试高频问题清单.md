# 国密面试高频问题清单（40 题）

> 四组：A 原理（10）、B Java 工程（10）、C 安全设计（10）、D 合规改造（10）。
> 简答要点按面试口径组织：先结论、再要点、能举例。标 ★ 为高频，标 ⚠ 为陷阱/情景题。

## A 组：原理

### A1 ★ 国密有哪些算法？什么场景用？
- SM2 椭圆曲线公钥（签名/加密/密钥交换，GB/T 32918、GM/T 0003）；SM3 杂凑 256bit（GB/T 32905、GM/T 0004）；SM4 分组对称 128bit（GB/T 32907、GM/T 0002）。
- SM9 标识密码（GM/T 0044）；ZUC 序列密码（GM/T 0001，移动通信 EEA3/EIA3）；SM1、SM7 算法不公开，仅在芯片/密码产品中使用。

### A2 ★ SM3 的参数与结构？
- 输出 256bit（32 字节），消息分组 512bit；填充后分组，消息扩展生成 W/W′，压缩函数 64 轮，IV 链接输出。
- 标准向量：`SM3("abc")=66c7f0f4...ba8e0`。

### A3 杂凑三性与生日攻击？
- 抗原像、抗第二原像、抗碰撞；n bit 输出的抗碰撞强度约 2^(n/2)，故 SM3 碰撞安全强度约 128bit。
- 推论：不能靠「随便加盐」弥补设计缺陷，也不能把 SM3 当口令保护方案。

### A4 ★ SM2 的数学基础？和 RSA 的区别？
- 基于椭圆曲线离散对数难题（ECDLP）；RSA 基于大整数分解。
- sm2p256v1 的 256bit 强度约等于 3072bit RSA，密钥更短、签名更小、速度更快。

### A5 SM2 默认用户 ID 是什么？为什么签名要 ID？
- 默认 `1234567812345678`（16 字节 ASCII）；签名先算 ZA=SM3(ENTL‖ID‖曲线与公钥参数)，把签名者身份绑定进摘要。
- 收发双方 ID 必须一致，否则验签失败。

### A6 ★ 简述 SM2 签名流程
- 算 ZA，再算 e=SM3(ZA‖M)；取随机数 k 得椭圆点 (x1,y1)，r=(e+x1) mod n，s=((1+dA)^−1 ·(k−r·dA)) mod n；签名 (r,s)。
- 验签是逆运算并校验 r 是否在 [1,n−1]。

### A7 ★ SM2 公钥加密的 C1C3C2 是什么？
- C1：随机数 k 产生的椭圆曲线点（04‖X‖Y，65 字节）；C2：与明文等长的密文（KDF 派生密钥流异或）；C3：SM3(x2‖M‖y2)，用于校验数据完整性。
- 国标现行顺序为 C1C3C2（GM/T 0009）。

### A8 C1C3C2 和 C1C2C3 的区别？04 前缀是什么？
- 仅 C2、C3 字段顺序不同，早期实现常用 C1C2C3；跨系统解密失败常见原因就是顺序不一致。
- 04 是椭圆曲线未压缩点标识，后跟 X(32)+Y(32)。

### A9 ★ SM4 参数？为什么加解密能用同一结构？
- 密钥/分组均 128bit，32 轮非平衡 Feistel 结构，含 S 盒、非线性变换 τ 与线性变换 L/L′；轮密钥由密钥扩展生成。
- Feistel 结构加解密算法相同，仅轮密钥使用顺序相反。

### A10 SM9 与 ZUC 的定位？
- SM9 是基于标识的密码：用户标识（如手机号/邮箱）即公钥，私钥由 KGC 生成，适合免证书跨域场景（GM/T 0044）。
- ZUC 是 128bit 序列密码，128bit 密钥 + IV，用于 4G/5G EEA3 加密、EIA3 完整性保护。

## B 组：Java 工程

### B1 ★ BouncyCastle 怎么用？
- 引入 `bcprov-jdk18on:1.84`，启动时 `Security.addProvider(new BouncyCastleProvider())`；各 JCE API 显式指定 `"BC"`。
- 不注册会抛 `NoSuchAlgorithmException: SM3`。

### B2 写 SM3 摘要并验证向量
- `MessageDigest.getInstance("SM3","BC").digest("abc".getBytes(UTF_8))`，Hex 编码应为 `66c7f0f4...ba8e0`。
- 大文件用多次 `update` 流式计算，避免一次性读入内存。

### B3 HMAC-SM3 和裸 SM3 的区别？
- HMAC 引入密钥：`H(K⊕opad ‖ H(K⊕ipad ‖ m))`，用于带密钥的完整性/认证，`Mac.getInstance("HMAC-SM3","BC")`。
- 裸 SM3 任何人都能重算，不能证明来源。

### B4 ★ 怎么生成 SM2 密钥对？公钥结构？
- `KeyPairGenerator.getInstance("EC","BC")` + `initialize(new ECNamedCurveGenParameterSpec("sm2p256v1"))`。
- 公钥未压缩点 65 字节 = `04`+X(32)+Y(32)；私钥 32 字节。

### B5 ★ SM2 签名代码要点
- `Signature "SM3withSM2"`，先 `setParameter(new SM2ParameterSpec(userId))` 再 `initSign`；对端用同一 ID 验签。
- 不设 ID 时 BC 有默认行为，但跨平台互通时必须显式约定，禁止依赖默认值。

### B6 DER 签名和 raw(r‖s) 区别？
- DER 是 `SEQUENCE{r INTEGER,s INTEGER}`（约 70~72 字节，长度随前导零变化）；raw 是定长 64 字节。
- 接口传输用哪种必须双方约定，混用必然验签失败。

### B7 ★ SM4 CBC 加解密
- `Cipher "SM4/CBC/PKCS5Padding"`；IV 16 字节随机生成、可随密文传输；密钥 `new SecretKeySpec(raw16,"SM4")`。
- IV 固定会泄露相同前缀等模式，等同部分失效。

### B8 ★ SM4 GCM 加解密；tag 和 AAD
- `Cipher "SM4/GCM/NoPadding"`，`GCMParameterSpec(128, nonce12)`；输出密文末尾带 16 字节 tag；`updateAAD` 处理附加认证数据。
- tag、key、nonce、AAD 任一不一致即 `BadPaddingException`。

### B9 大文件/流式加密注意什么
- 用 `CipherInputStream/OutputStream`；CBC 按 16 字节分块，GCM 全流一个 tag，中途无法独立解密分段，需分块则自行管理每块 nonce/tag。
- 文件名、分片序号可放进 AAD 防替换。

### B10 常见报错怎么排
- `NoSuchAlgorithmException`：未注册 BC/版本过低；SM2 Key 类型错误：密钥需 BC 体系或做转换。
- `BadPaddingException`：GCM tag 不匹配或 CBC 填充/密钥/IV 错；先拿标准向量排除代码问题，再查参数与编码。

## C 组：安全设计

### C1 ⚠ 陷阱题：用 SM3 存口令行不行？
- **不行。** SM3 是快速哈希，GPU/ASIC 可高速爆破，且相同口令摘要相同，彩虹表/撞库有效。
- 必须用加盐慢哈希/KDF：PBKDF2、Argon2、bcrypt 等，设置足够迭代次数/成本；SM3 不承担口令存储职责。

### C2 ⚠ 情景题：存量系统 SM4 的 IV 是固定值，怎么办？
- 定性：密钥不变时固定 IV 使相同明文产生相同密文，泄露数据模式；GCM 下 nonce 复用后果更严重（可恢复明文、伪造）。
- 处置：①定级与影响面排查；②改为每次加密随机 IV（CBC 16 字节/GCM 建议 12 字节）并随密文存储；③历史密文制定重加密计划；④增加「IV 唯一性」检测与告警；⑤验证与回归后纳入规范红线。

### C3 ★ 为什么禁用 ECB？
- 相同明文块产生相同密文块，保留数据模式（经典「加密位图」），且无 IV、易被篡改/重排块。
- ECB 仅可用于单块且无语义的数据（如一次性随机密钥），业务数据用 CBC（随机 IV）或 GCM。

### C4 IV/nonce 需要保密吗？复用什么后果？
- 不保密，但必须不可预测（CBC）或在同密钥下唯一（GCM 推荐随机 96bit）。
- CBC IV 固定泄露模式；GCM nonce 复用会暴露认证密钥，可解密密文并伪造 tag，属严重事故。

### C5 ★ 怎么防重放？只加哈希够吗？
- 不够：哈希/摘要不防重放也不证明来源。
- 标准做法：时间戳 + 唯一 nonce（服务端去重窗口）+ 密钥签名/HMAC；必要时加单调序列号、一次性 token、幂等键。

### C6 密钥分层与信封加密
- DEK 加密业务数据，KEK 加密 DEK；DEK 随密文存（已封装），KEK 放 KMS/HSM 不出安全边界。
- 典型：用 SM2 或 KMS 封装随机 SM4 DEK，轮换 DEK 不动主密钥，缩小泄露影响面。

### C7 随机数怎么选？
- 密码场景必须用 `SecureRandom`（底层 OS 熵源），禁止 `Math.random`/`java.util.Random`。
- Linux 上注意 `/dev/random` 阻塞导致启动卡顿，可用 `/dev/./urandom` 或评估 `getInstanceStrong()` 后按场景选型。

### C8 GCM 和 CBC 怎么选？
- GCM 提供认证加密（机密性+完整性，带 AAD），新系统优先；CBC 只提供机密性，需另配 HMAC（先 MAC 后加密等规范顺序）。
- 选型还要看对端支持、硬件加速与性能基线。

### C9 签名和加密如何搭配？
- 要同时保证「机密性 + 不可否认」时：发送方先用自己 SM2 私钥签名，再用接收方公钥/对称密钥加密（签名随密文保护）。
- 对称加密数据、非对称传密钥（信封）；不要用同一把 SM4 既做加密又裸做校验密钥，按用途派生子密钥。

### C10 ★ 跨系统加解密对不上，怎么排查？
- 顺序：编码（Hex/Base64）→ 用户 ID → 报文拼接顺序 → 模式与填充（PKCS5/7、GCM tag 位置）→ 密文结构（C1C3C2、04 前缀）→ 密钥字节本身。
- 用标准向量与极简报文逐步对拍，保留双方原始字节 Hex，禁止只对比「看起来差不多」的字符串。

## D 组：合规改造

### D1 ★ 什么是密评？依据什么？
- 商用密码应用安全性评估：对密码方案、应用、运维的合规性与有效性评估；依据 GB/T 39786、GM/T 0054 等。
- 关键信息基础设施等重要系统需依法定期开展，分规划评估、建设评估、运行评估。

### D2 密评和等保 2.0 的关系
- 等保（GB 22239）是网络安全等级保护的总体框架；密评聚焦「密码使用是否合规有效」，是等保在密码维度的支撑与细化。
- 实践中两者协同：等保定级备案，密评检验密码措施。

### D3 ★ 国密改造第一步做什么？
- 密码资产盘点：数据分级、现有算法/协议/证书/密钥位置、厂商组件、外连接口，形成台账并按风险排序。
- 没有台账就没有改造范围，也无法回答密评「哪里用了密码」。

### D4 双证书是什么？
- GM/T 0015 体系下签名证书 + 加密证书；签名证书私钥用户自持、不可否认；加密证书私钥常由密钥管理中心/系统托管，支持密钥恢复与合规监听。
- 国密 TLS（GM/T 0024）普遍使用双证书双向认证。

### D5 ★ 双栈过渡与回退怎么设计？
- 新旧算法/协议并行（如标准 TLS + TLCP、RSA + SM2 证书），按灰度流量切换，配置中心控制开关。
- 回退必须限时、可观测并登记，禁止长期保留不安全兜底；防止 downgrade 攻击。

### D6 证书过期、时钟不同步有什么风险？
- 证书过期导致批量业务中断；时钟偏移使证书有效期、时间戳、nonce 窗口校验全部出错。
- 需证书生命周期监控（到期告警/自动续期）、统一 NTP、证书与密钥台账。

### D7 ★ KMS、HSM、SDF 的区别
- KMS 是密钥管理服务（托管/轮换/权限）；HSM 是硬件安全模块（防物理篡改的密钥运算）；SDF（GM/T 0018）是国内密码设备的标准接口。
- 一般业务用 KMS 封装 DEK；高安全场景私钥/主密钥运算进 HSM 或通过 SDF 接密码机。

### D8 TLCP 和标准 TLS 的差异
- GM/T 0024 的 TLCP 采用 SM2/SM3/SM4 与双证书，握手套件、证书类型为国密定制；国密 TLS 相关规范还在演进，部署以现行版本为准。
- 工程上常通过国密网关/支持库实现，浏览器与客户端生态需同步评估。

### D9 ★ 存量明文数据怎么加密迁移
- 选高敏字段优先；方案：影子列双写（明文+密文）→ 读校验 → 切读密文 → 停写明文并历史数据分批重加密 → 回收明文列。
- 全程校验、限速、可回滚；密钥用 DEK/KEK 分层，避免改造中泄露备份明文。

### D10 怎么向管理层汇报改造
- 讲四件事：合规差距与义务（不做的法律/业务风险）、资产与风险分级、路线图与里程碑、资源投入与收益。
- 用数据说话：多少系统/字段/证书、预计停机窗口、双栈周期、迎检时间点，而不是「密码很重要」的空泛表述。
