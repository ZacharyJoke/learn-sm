# 后续扩展方向

> 七个方向，每个按「问题 → 机会 → 切入项目」组织，适合作为进阶选题、开源作品或团队预研。
> 原则：区分事实与推测，涉及未发布标准（如国密 PQC）一律注明以官方发布为准。

## 一、抗量子密码（PQC）与国密过渡

- 问题：量子计算威胁现有公钥体系——Shor 算法可破 RSA、ECC（含 SM2）；SM3/SM4 受 Grover 影响为安全强度减半，可通过加长度缓解。NIST 已选定 ML-KEM（Kyber）、ML-DSA（Dilithium）等标准，国密 PQC 以国家密码管理部门官方发布为准，不臆测算法与参数。
- 机会：迁移窗口长（10 年级），现在需要的是「可观测的混合过渡」：混合签名（经典签名 + PQC 签名并存）、混合 KEM（经典/椭圆曲线密钥交换与 PQC KEM 组合，任一安全则会话安全）、密码资产的「PQC 就绪度」清单。
- 切入项目：①盘点系统中所有非对称算法与证书依赖，产出量子风险台账；②在一条非关键链路上实现 SM2 + PQC 双签名或混合密钥封装原型；③设计协议版本协商字段，为未来算法替换留扩展位。

## 二、云原生密码能力

- 问题：K8s 环境中 Secret 默认只是 Base64、容器内存易被 dump、证书与节点身份管理分散；静态加密、传输加密、密钥轮换难以统一治理。
- 机会：云厂商 KMS + 外部密钥服务（如 External Secrets 模式）；服务网格原生 mTLS；Sidecar/节点代理卸载密码运算，业务无感知。
- 切入项目：①用 KMS + Secrets Operator 实现 Secret 加密落盘与自动轮换；②在 Mesh 中落地短期工作负载证书与 mTLS；③Sidecar 统一做签名验签与加解密，对比改造前后的业务侵入度与延迟。

## 三、国密网关与 API 安全

- 问题：外部客户端（浏览器/合作方）国密支持参差，内部服务又需要全链路国密；API 还面临重放、篡改、越权调用。
- 机会：在网关层做协议转换（外部 TLS ↔ 内部 TLCP/国密 mTLS）、统一证书卸载、统一签名校验与流量加解密；把密码策略从业务代码抽离。
- 切入项目：基于开源网关（APISIX/ Kong 等）+ 国密插件实现：①国密 TLS 卸载与双证书；②统一验签（时间戳+nonce+SM2 签名）与限流；③按路由的字段级加解密策略。

## 四、Spring Boot Starter 密码中间件

- 问题：各团队重复封装 BC，算法参数、IV 规则、异常处理不一致，审计口径无法统一。
- 机会：一个「约定优于配置」的 Starter：自动注册 BC、注解驱动字段加解密、统一信封加密、KMS 适配层、密码操作指标与审计事件。
- 切入项目：实现 `@Sm4Field`（GCM、自动 IV）、`@Sm2Sign`（统一 ID 与拼接）、KMS SPI；输出配置元数据、兼容性测试矩阵与性能报告，作为团队级标准组件推广。

## 五、密评自动化

- 问题：密评依赖人工访谈与截图，证据容易过期；系统一变更就与上次结论脱节。
- 机会：把检查项代码化：扫描代码与镜像中的算法/弱模式、采集证书与协议配置、检测 IV/nonce 与密钥来源、持续生成符合性报告。
- 切入项目：对照 `templates/03-安全审计检查清单.md` 做规则引擎（SAST 规则 + 运行时探针 + 证书台账），产出趋势看板与整改工单联动，先在 CI 中拦截 ECB、硬编码密钥等高确定项。

## 六、HSM 即服务（HSMaaS）

- 问题：传统密码机按项目采购、贵且利用率低；多团队直接对接 SDF（GM/T 0018）成本高、故障域分散。
- 机会：把 HSM 池化、服务化：统一配额、多租户隔离、审计与高可用；上层提供签名、封装、随机数等标准 API，底层对多型号密码机做适配。
- 切入项目：在实验环境搭「SDF 代理 + 租户配额 + 操作审计」服务，提供 Java SDK；压测签名 QPS 与故障切换，输出 SLA 与成本对比。

## 七、物联网轻量密码

- 问题：物联网终端算力/功耗/存储空间受限，跑不动证书体系与长握手；设备身份又海量、易被仿冒，固件易被篡改。
- 机会：轻量认证（预共享密钥派生、SM9 标识免证书）、安全启动与固件签名（SM2/SM3）、通信层用 SM4 或 ZUC 类流密码降低开销；密钥按设备一机一密。
- 切入项目：做一个「设备注册 → 一机一密下发 → SM4-GCM/ZUC 通信 + 固件 SM2 签名校验」的端云最小闭环，统计握手流量、RAM/Flash 占用与耗电。

## 选题建议

- 作品要同时包含「可运行代码 + 威胁分析 + 数据指标」，三者齐全才区别于 demo。
- 涉及未发布标准的研究，明确标注「现状/推测/待官方确认」，避免把路线猜想写成结论。
